## 通用积木

根据 lesson plan 组合以下积木：学习目标、前置知识、引导问题、直觉解释、正式定义、机制拆解、分步过程、图示或数据流、代码演进、脆弱实现与正确实现对照、实验、真实案例、常见误区、局限和边界、故障排查、速查卡、练习题、面试题、本页回顾、来源列表。

每个积木承担可说明的教学作用。页面允许省略与学习目标无关的积木。

## 完成专题要求

状态为 `completed` 的深度页应包含：

- 明确的学习目标与必要前置知识。
- 与主要教学模式匹配的讲解顺序。
- 具体例子与可核验结果；代码、受控实验和交互演示按学习目标选用。
- 常见错误、边界条件或局限。
- 可复习的结论区域。
- 与正文主张对应的来源。
- 键盘、屏幕阅读器、打印和减少动态支持。

首页、分类页和规划项只承担导航与课程规划功能。

## 教学节奏

按主题选择讲解路径：

- 从问题进入机制。
- 从直觉进入正式定义。
- 从失败代码进入修复过程。
- 从实际工作流进入原理解释。
- 从真实案例进入根因分析。
- 从实验现象进入理论归纳。

比喻只在能减少理解步骤时使用。比喻后给出技术定义，并说明适用边界。章节顺序依据学习目标调整，避免模板化排列。

## 专题编排

### 安全漏洞专题

优先组合学习目标、前置知识、威胁模型、信任边界、根因、攻击条件、请求或数据流、授权实验、脆弱与安全代码、检测、缓解、架构防御、真实案例、适用考核、来源与安全声明。

### 概念和学术专题

优先组合学习目标、直觉例子、正式定义、机制或推导、参数、边界、误区、局限、来源。练习和交互实验只在 lesson plan 需要时加入。

### 机器学习通识专题

按任务形式化、数据表示、目标函数、优化、泛化、神经网络、反向传播、架构选择、生产监控建立完整主线。每个数学概念同时给出符号定义、可计算的小例子和工程含义。训练动画聚焦一条因果链，例如“权重 → 预测 → 损失 → 梯度 → 参数更新”；页面始终保留静态公式、固定数值记录和文字结论，供无 JavaScript、减少动态效果与打印场景阅读。

### AI Agent 工程演进专题

按工程对象组织 Prompt、协议、Skills、上下文、Harness、Loop 与 Graph 等层级，并说明各层长期并存。每层至少回答：设计对象是什么、解决什么问题、产出什么工程工件、相邻责任边界在哪里。新兴术语先说明传播来源和成熟度，再用协议规范、官方框架文档或原始论文解释底层机制；同名概念存在知识图谱、执行图等歧义时先划定范围。顺序演进使用静态 `StepList` 或全宽表，机制复杂处再使用图示。

### 编程语言专题

优先组合运行模型、必要语法、最小可运行示例、代码演进、内存或执行流程、常见错误、调试、练习、速查卡、来源。

### 工具和工作流专题

优先组合目标版本、环境、安装配置、最小成功路径、常用工作流、命令与输出、诊断路径、速查卡、实践任务、官方来源和验证日期。

### 零基础课堂课

面向没有编程和命令行经验的学员、由讲师当堂带着做的入门课（语言基础、命令行、Git、Docker 等）。在上面两类编排的基础上追加：

- 一课对应一次线下课。`segments` 三段分别是讲解（必读）、当堂跟做（动手）、收尾与作业（进阶），用时之和等于 `durationMinutes`。
- 先给最小成功路径，再讲机制。学员在十分钟内应当亲手得到第一个正确结果。
- 每条命令同屏给出实际输出，并说明哪一行是学员敲的、哪一行是机器返回的。输出来自目标环境的真实运行，不手写。
- 写明目标环境（操作系统、发行版、工具版本）。学员环境与讲师环境不同时，以学员环境为准。
- 每次运行都会变的输出（进度、速度、对象计数）用一行以「…」开头的说明代替，并写明省略了什么；其余行保持原样。
- 单列「常见报错」：报错原文、原因、处理办法。选学员最容易撞上的三到五个。
- 验收题三个槽位：机制判断、预测输出（`prediction`）或读数计算、小型实践。实践题给出可自查的预期结果。
- 课后作业另列，不计入课堂用时，并提供可下载的起步文件。
- 借鉴公开教程时只取章节顺序与例子思路，正文自写；事实仍按证据档案绑定官方文档、规范或教材，教程本身列入延伸阅读。

### 项目实践专题

优先组合最终成果、环境依赖、架构、分阶段实施、阶段验收、调试、完整验收和扩展任务。

### 比较专题

先确定统一比较维度，再解释差异、约束、适用场景和选择建议。结论绑定用户场景。

### 故障排查专题

从可观察症状开始，建立低成本到高成本的诊断路径。每个原因提供验证信号与修复后的复查方法。

## 正文规则

- 默认使用简体中文和“你”。
- 术语首次出现时给出定义。
- 段落保持短小，长内容用小节、图示、代码、表格或交互形成阅读断点。
- 代码示例包含运行方式、环境和预期结果；用于建立直觉的演示须**直接展示结果**，不能只贴 shell 命令。
- 主张使用 manifest 中的来源 ID 建立追溯关系。
- 重点结论卡数量遵循 policy，并只承载最需要复习的结论。
- 页面避免口号和无信息装饰。
- 事实、版本、命令、CVE、论文、案例和统计只写入已经核验的内容。
- 页面本身即讲义：禁止“讲义里写到……”“本节课我们会……”等空转元叙述。
- 基于用户 PDF/旧页转写时，保留关键例子与数量级示意，禁止压成只有标题和一句话的摘要条；删除图示须有替代理解路径。
- 遵循 nofluff：使用直接肯定句，禁假对立、空比喻与情绪夸大。

## 安全内容

- 实验目标使用 localhost、容器、CTF 靶场或明确授权系统。
- 域名、IP、密钥和身份信息使用安全占位值。
- payload 与 HTML 字符串经过转义，培训站点不会执行示例。
- 高风险命令说明影响范围和恢复方式。
- 内容不提供针对公共目标的扫描、持久化、凭据窃取或破坏步骤。
- 防御部分按主题覆盖输入验证、输出编码、权限边界、日志、检测和修复验证。
- 安全专题使用统一安全声明组件。
