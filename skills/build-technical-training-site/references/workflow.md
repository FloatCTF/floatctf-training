## 运行前检查

读取目标目录树、项目清单、包管理文件、Astro 配置、catalog、lesson manifest、内容页面、主题配置、生成脚本和质量报告。目标目录位于 Git 仓库时，读取工作区状态和相关差异。记录用户已有修改，只处理当前任务涉及的文件。

识别以下情况：

- 空目录或缺少站点入口。
- 已存在 Astro 或 Starlight 站点。
- 已存在同 ID、slug、标题或页面路径的专题。
- catalog、manifest、MDX 或导航之间存在不一致。
- 构建产物、依赖目录和临时文件是否需要排除。

## 需求推断

优先使用用户请求、现有 catalog、相邻专题和站点配置。默认值从 `assets/starter/config/training-policy.json` 的 `defaults` 读取。

受众、内容深度或工作模式缺失且会改变信息架构时，提出必要问题。问题数量遵循 policy。其余缺失项使用默认值，并在 lesson plan 中显式记录。

## 模式选择

- 目标目录没有培训站点，选择 `create-site`。
- 站点存在且用户要求新专题，选择 `add-topic`。
- 专题存在且用户要求更新事实、版本、案例、命令或交互，选择 `refresh-topic`。
- 用户要求检查、修复或验收站点，选择 `validate-site`。
- 用户只需要分类、路线、排期或专题状态，选择 `plan-curriculum`。

一次调用选择一个主模式。发现阻断性质量问题时，可在主模式末尾执行 `validate-site` 的修复环节。

## 通用专题流程

1. 读取 catalog 与相邻专题，确认分类、ID、slug、前置关系和页面路径。
2. 创建或更新 lesson manifest 中的 lesson plan。
3. 检查 lesson plan 与主题、受众、时长、考核和视觉叙事的匹配度。
4. 若有用户 PDF/旧页：先拆“结构层 / 事实层”，再按 evidence profile 检索；勿把用户材料当唯一事实源。
5. 按教学模式选择内容积木和讲解节奏；动效只服务高理解成本关系。
6. 编写或增量修改 MDX，复用现有组件；教学表用 Grid DataTable，演示结果上屏。
7. 更新 catalog；规划项保留空页面路径。
8. 生成主题，运行结构门禁、Astro 检查和生产构建。
9. 完成定性自审与 lessons-learned 强制自检；当前环境有浏览器能力时追加浏览器验证并刷新本专题 QA 证据。
10. 仅在用户要求或仓库惯例需要时再 git commit；“先看效果”不等于跳过第 9 步。

## `create-site`

1. 确认目标目录可以写入，并记录其中已有文件。
2. 将 `assets/starter/` 内容复制到目标目录，排除依赖目录、构建目录和测试截图。
3. 将浏览器相关 QA 项重置为 `not-run`，清空 `qa/browser-report.json` 的页面、检查和截图记录。
4. 调整站点标题、site、base、catalog 和首批 lesson plan。
5. 为新增专题完成通用专题流程。
6. 生成锁文件时保留兼容版本范围，锁定实际安装版本。
7. 使用干净安装和完整验收命令验证站点。

## `add-topic`

1. 检查 ID、slug、路径和推荐前置专题是否冲突。
2. 先创建 manifest，再创建 MDX。
3. 在 catalog 对应分类登记专题。
4. 运行一致性验证，确认首页、分类页和侧边栏自动更新。
5. 只在新专题需要时增加通用组件。

## `refresh-topic`

1. 读取现有页面、manifest、catalog 和相关差异。
2. 标记需要更新的事实、版本、来源、命令、案例、考核和交互。
3. 保留仍准确的结构与用户文案，增量替换过期内容。
4. 更新 `verifiedAt`、`accessedAt`、版本差异和研究状态。
5. 重新验证所有被修改的引用关系与交互降级。

## `validate-site`

1. 使用锁文件安装依赖。
2. 执行统一验收命令并保留完整错误输出。
3. 按错误中的文件、专题 ID 和字段定位根因。
4. 修复内容结构、类型、构建、主题对比度和无障碍问题。
5. 完成定性自审；当前环境有浏览器能力时执行浏览器矩阵。
6. 修复后重新执行统一验收命令。

## `plan-curriculum`

1. 建立或更新分类、顺序、简介和学习路线。
2. 为拟建专题写 catalog 条目，状态设为 `planned`，页面路径设为空值。
3. 记录推荐前置专题与难度。
4. 运行 catalog 一致性验证。
5. 停止在课程规划层，不创建专题正文或伪来源。

## 文件保护

- 修改前读取目标文件和工作区差异。
- 保留无关改动与用户自定义组件。
- 覆盖专题前比较 catalog、manifest 与正文，确定最小增量范围。
- 不执行会丢弃提交、工作树或未跟踪文件的 Git 操作。
- 自动生成文件只由对应生成脚本更新。
- 删除文件前确认该文件只服务于当前任务，并保留可恢复记录。

## 交付记录

记录实际模式、修改文件、来源验证日期、依赖版本和验收命令。浏览器验证已执行时记录矩阵，缺少对应能力时记录 `not-run` 和原因。任何已执行的必须项失败时保留失败状态和修复建议。
