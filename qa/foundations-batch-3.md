## 验证证据

- **命令重放**：两课页面上的 104 条命令在 Kali 容器（git 2.53.0）里按页面顺序重放，104 条一致。其中 4 条推送和拉取的输出在页面上省略了传输进度（对象数、线程数、速度因机器而异），其余行逐字比对。
- **提交哈希可复现**：重放时固定了提交时间和作者，页面上九个提交的哈希每次重放都相同；提交图数据里的哈希与终端会话里的一致。页面明确告诉学员他们自己的哈希会不同。
- **提交图**：两份数据由 `git-trace.py` 执行真实命令后读取 `git status`、`git log` 生成，不是手画。浏览器里逐步点击，每一步的三栏内容与数据一致，记录在验证文件里。
- **不在页面流程中的报错**：常见情况表里的六条报错（未配置身份、没有暂存就提交、推送被拒、分叉后 pull、带着改动切分支、删除未合并分支）另在容器里复现后抄录。
- **练习答案**：第 11 课验收第 3 题的参考步骤、作业里「提交过的内容删不掉」的实验，在容器里跑过，结果与页面描述一致。
- **来源**：Pro Git 第二版七节、Git 官方手册六页、GitHub 官方文档两页、MIT Missing Semester 一讲，共 16 个页面，全部打开原页核对，逐条论断对得上原文。
- **浏览器**：两课在 1280 与 390 两种宽度、深浅主题下共 6 次检查，HTTP 200、单一 H1、整页横向溢出为零、页内锚点无断链、控制台无报错。减少动态与关闭 JavaScript 时提交图显示最终状态和逐步表；打印媒体模拟下答案与终端会话可见。
- **构建**：`npm run verify` 通过。

## 看截图后改掉的三处

- 提交图里跨泳道的连线原先是一条大弧，会贴着中间的提交划过去。改成只在一行之内拐弯，其余部分贴着泳道走直线。
- 手机宽度下提交编号被分支标签挤得折成两行。改成分支标签换到提交说明的下一行，行高不变。
- `git add` 之后，工作区一栏把文件标成「无改动」，容易让人以为什么都没发生。改成「已暂存」。

## 写课时定下的约定

- **用 echo 生成文件内容。** 所有人的文件完全一致，提交图才能和页面对得上；正文说明了实际工作中用编辑器。
- **远程仓库用本机的裸仓库代替，「队友」是另一份克隆。** 不需要账号和网络，命令与连接 GitHub 时相同。
- **只教 `git switch` 和 `git restore`**，在第 12 课点一句旧写法 `git checkout -b` 与它等价，因为本站 README 和很多教程还在用。
- **第 11 课的作业不动 `~/lab/toolbox`**，这个仓库第 12 课接着用。
- **撤销只讲到「还没提交的改动」。** `commit --amend`、`reset`、`rebase`、`stash` 没有讲，常见情况表里只提了一句 `--amend`。

## 未覆盖范围

- **GitHub 上的操作没有实跑。** 注册账号、配置 SSH 密钥或令牌、在网页上创建和合并 PR 都没有写成步骤，第 12 课只依据 GitHub 官方文档和本站 README 讲流程。学员第一次真正向社团仓库提 PR 时，需要有人当面带一遍。
- 忘了 `-m` 时打开的编辑器，容器里是 nano。真实 Kali 桌面上的默认编辑器没有核对，页面只写了 nano 的退出方式。
- 没有在真实的 Kali 虚拟机桌面上操作过。
- 真实移动设备、屏幕阅读器、纸张分页、生产 nginx 与 CSP 未验收。
