## 引导问题：怎样把一个环境原样交给别人

这学期你在 Kali 里装过 PHP、SQLite 驱动、gdb，每装一样就多一条命令。假设社团要给三十个人发一个练习环境：一个特定版本的 PHP、一个数据库、几份配置文件。

让每个人照着文档自己装，总有人版本不对、漏了一步、改错了配置。第 1 课的虚拟机能解决这个问题，可是一个虚拟机动辄几个 GB，启动一次要一分钟。

Docker 的做法是：把环境做成一个**镜像**，大家拿到同一个镜像，各自运行出一个**容器**。容器里的东西和做镜像的人那里一模一样，启动只要一两秒。

### 2. 容器和虚拟机

<NestedLayers
  eyebrow="LAYERS / 再往里一层"
  title="容器在第 1 课那张图的哪里"
  layers={layers}
  note="虚拟机模拟的是一整台电脑，里面要装一整套操作系统；容器只是一个被隔离开的进程，借用所在系统的内核。"
/>

Docker 官方的说法：虚拟机是一整套操作系统，有自己的内核、驱动和程序；容器只是一个带着运行所需文件的隔离进程，多个容器共用同一个内核。所以容器小、启动快，一台机器上能同时跑很多个。（来源：[What is a container?](#source-dk-container)）

### 3. 安装

Kali 默认没有装 Docker。在虚拟机里执行：

<TerminalSession
  replay="skip"
  title="安装 Docker（只需一次）"
  steps={[
    { cmd: 'sudo apt install -y docker.io docker-buildx docker-compose', note: 'docker.io 是 Docker 本身，另外两个下一课用。' },
    { cmd: 'sudo usermod -aG docker $USER', note: '把自己加进 docker 组，以后不用每条命令都加 sudo。' },
  ]}
/>

加完组之后，**注销再重新登录**（或者重启虚拟机），新的组才会生效。没生效时会看到 `permission denied while trying to connect to the Docker daemon socket`。

<Callout variant="warning" title="docker 组等于 root">
Docker 官方文档明确写着：docker 组相当于授予了 root 级别的权限。能使用 Docker 的人，可以让容器挂载系统的任何目录。在自己的练习虚拟机里这样配置没有问题；在多人共用的服务器上，不要随手把人加进 docker 组。
</Callout>

（来源：[Linux post-installation steps](#source-dk-postinstall)）

## 二、容器的一生

### 1. 在后台跑一个网站

<TerminalSession
  title="启动 nginx，发布到本机 8080 端口"

/>

<DataTable
  caption="docker run -d --name web -p 8080:80 nginx:alpine"
  headers={["部分", "含义"]}

容器有自己独立的网络，里面的 nginx 监听的是容器自己的 80 端口，外面默认访问不到。`-p` 在隔离上开了一个口子：发到本机 8080 端口的请求，转发给容器的 80 端口。第 13 课讲的地址和端口在这里全都用上了。（来源：[Publishing and exposing ports](#source-dk-publishing)、[docker container run](#source-dk-run)）

### 3. 删掉容器，改动也没了

<TerminalSession
  title="在容器里改首页，然后重建容器"
  steps={[
    { cmd: "docker exec web sh -c 'echo hello from inside > /usr/share/nginx/html/index.html'" },
    { cmd: 'curl -s http://127.0.0.1:8080/', out: 'hello from inside', note: '首页被改了。' },
    { cmd: 'docker rm -f web', out: 'web', note: 'rm 删除容器，-f 表示正在运行也强制删。' },
    { cmd: 'docker run -d --name web -p 8080:80 nginx:alpine', out: 'aae24181b1066c73727ac7ed5146e2474b3378e1beee5608315dbde94ae7df64', note: '这次没有下载：镜像已经在本地了。' },
    { cmd: "curl -s http://127.0.0.1:8080/ | grep title", out: '<title>Welcome to nginx!</title>', note: '又是默认首页。' },
    { cmd: 'docker rm -f web', out: 'web' },
  ]}
/>

镜像是只读的。容器运行时对文件的改动，记在这个容器自己的一层里；删除容器，这一层也随之删除。新容器又从原封不动的镜像开始。这是 Docker 好用的地方：环境搞乱了，删掉重来就是干净的。但它也意味着：**要留下来的数据，不能只放在容器里。**（来源：[Persisting container data](#source-dk-persisting)、[What is an image?](#source-dk-image)）

## 三、数据放在容器外面

### 1. 绑定挂载：用本机的目录

<TerminalSession
  title="把本机的目录挂进容器"
  steps={[
    { cmd: 'mkdir -p ~/lab/docker/site' },
    { cmd: 'cd ~/lab/docker' },
    { cmd: "echo '<h1>my site</h1>' > site/index.html" },
    { cmd: 'docker run -d --name web -p 8080:80 -v ~/lab/docker/site:/usr/share/nginx/html:ro nginx:alpine', out: '1ddec42e1e843b3e3643f2819c4fe7a9e751dd4cd81a297430fb07b4f0d2f402', note: '-v 本机目录:容器里的目录。末尾的 :ro 表示容器只能读不能写。' },
    { cmd: 'curl -s http://127.0.0.1:8080/', out: '<h1>my site</h1>' },
    { cmd: "echo '<h1>my site, edited</h1>' > site/index.html", note: '在本机改文件。' },
    { cmd: 'curl -s http://127.0.0.1:8080/', out: '<h1>my site, edited</h1>', note: '容器里立刻看到了，不用重启。' },
  ]}
/>

**绑定挂载**把本机的一个目录直接挂到容器里的某个位置，两边看到的是同一份文件。写代码时很方便：在本机用编辑器改，容器里马上生效；容器删掉，文件还在本机。（来源：[Bind mounts](#source-dk-bind-mounts)、[Sharing local files](#source-dk-sharing)）

### 2. 卷：交给 Docker 保管

<TerminalSession
  title="两个容器先后用同一个卷"
  steps={[
    { cmd: 'docker volume create notes', out: 'notes' },
    { cmd: "docker run --rm -v notes:/data nginx:alpine sh -c 'echo first note > /data/notes.txt'", note: '--rm 让这个容器执行完就自动删除。它往卷里写了一个文件。' },
    { cmd: 'docker run --rm -v notes:/data nginx:alpine cat /data/notes.txt', out: 'first note', note: '另一个全新的容器挂上同一个卷，读到了刚才写的内容。' },
    { cmd: "docker volume ls --format '{{.Name}}'", out: 'notes' },
  ]}
/>

**卷**是由 Docker 创建和管理的一块存储，写法和绑定挂载一样，冒号左边写卷的名字而不是路径。它不属于任何容器，容器删了它还在。数据库的数据文件通常放在卷里。（来源：[Volumes](#source-dk-volumes)）

边界：容器的隔离不等于虚拟机的隔离。容器共用宿主的内核，以特权方式运行或者挂载了敏感目录的容器，能影响到宿主。下学期跑来路不明的靶场镜像时，放在练习虚拟机里运行，不要放在自己的主力系统上。

<KeyTakeaway>
镜像是只读的环境模板，容器是由镜像运行起来的隔离进程，镜像仓库存放和分享镜像。容器共用宿主的内核，所以比虚拟机小得多、快得多。`docker run` 加 `-p` 把容器的端口发布到本机，`ps`、`logs`、`exec`、`rm` 管理容器的一生。容器删除时，它在镜像之上做的改动也一起消失；要保留的数据用绑定挂载放在本机目录，或者放进由 Docker 管理的卷。
</KeyTakeaway>
