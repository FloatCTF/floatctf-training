## 引导问题：为什么“服务器没被入侵”，用户还是会中招？

SQL 注入主要改服务器侧数据访问；XSS 把不可信数据变成浏览器会执行的脚本或事件。受害者是打开页面的用户会话、页面内容和后续操作。

CWE-79 将其描述为网页生成期间未正确中和输入；OWASP 给出按上下文选择编码器与安全汇点的规则。（来源：[CWE-79](#source-cwe-79)、[OWASP](#source-owasp-xss-prevention)）

## 输出上下文决定编码

同一段输入出现在不同位置，危险形态不同：

1. **HTML 文本：** 需要 HTML 编码，防止长出新标签。
2. **HTML 属性：** 需要属性编码，并优先使用引号包裹。
3. **JavaScript：** 只把数据放入加引号的数据值位置，并使用成熟的 JavaScript 编码器；优先把数据放进独立 JSON 响应或 DOM 属性。
4. **URL：** 先限制协议，再对参数使用 `URLSearchParams` 或 `encodeURIComponent`；写入 `href`、`src` 时仍需安全属性 API。
5. **CSS：** 避免动态拼接样式文本；确有业务需要时使用受限属性和值，并采用对应编码规则。

<Callout variant="warning" title="入口过滤不等于输出安全">
数据可能在服务端、消息队列、模板和前端路由间多次流转。编码应发生在进入对应上下文的输出边界。
</Callout>

## 真实案例

CVE-2023-27898 影响 Jenkins 2.270–2.393 与 LTS 2.277.1–2.375.3：插件管理器未转义插件依赖的 Jenkins 版本错误消息；攻击者还需要向已配置更新站点提供插件并让实例显示该消息。修复版本为 2.394、LTS 2.375.4 与 2.387.1。CVE-2023-1932 是 Hibernate Validator `SafeHtmlValidator.isValid` 的校验绕过，浏览器可能把无效 HTML 解释为 HTML 注入或 XSS。（来源：[CVE-2023-27898](#source-cve-2023-27898)、[Jenkins 公告](#source-jenkins-cve-2023-27898)、[CVE-2023-1932](#source-cve-2023-1932)、[NVD](#source-nvd-cve-2023-1932)）

## 常见错误与边界

- **只做标签黑名单。** 事件属性与编码变体很多。
- **在 JS 上下文使用 HTML 编码。** 上下文错配。
- **以为 HttpOnly 等于 XSS 已修复。**
- **富文本消毒策略与业务需求冲突时缺少明确允许标签表。**

<KeyTakeaway>
XSS 的关键判断是浏览器将在哪个上下文解释不可信数据。优先使用安全汇点和默认转义模板；需要编码时匹配具体上下文；CSP 与 Cookie 属性承担纵深防御。
