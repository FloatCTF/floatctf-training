## 引导问题：单引号为什么能改写查询？

登录接口把用户名和密码拼进：

```sql
SELECT * FROM users WHERE username='...' AND password='...'
```

以本页 SQLite 实验为例，用户名 `admin' --` 会提前结束字符串字面量，并用 `--` 注释输入末尾的密码条件。注释和字符串语法随数据库方言变化，验证前必须确认目标方言。

CWE-89 将这类问题描述为未正确中和 SQL 命令中的特殊元素；OWASP 强调应把不可信数据与语句结构分离。（来源：[CWE-89](#source-cwe-89)、[OWASP](#source-owasp-sqli-prevention)）

## 机制：从字符串到执行计划

1. **输入进入查询构造。** 登录、搜索和筛选中的值可能被拼进 SQL；排序字段和表名属于标识符，需要单独设计。
2. **解析完整查询文本。** 数据库对应用提交的整段 SQL 做词法和语法分析。
3. **输入影响解析结果。** 提前闭合引号、增加操作符或注释后续文本，会形成应用未预期的语法结构。
4. **优化并执行。** 数据库按解析后的语义生成执行方案。
5. **权限决定影响。** 数据库账号可读写的对象和可调用功能决定影响范围。

成立条件可以写成：**应用用字符串构造 SQL + 输入影响该字符串 + 缺少结构绑定或等价安全 API**。

<Callout variant="warning" title="过滤单引号不是主防线">
不同数据库、编码转换、数值上下文和二次拼接都会让字符黑名单失效。优先固定语句结构，再处理业务允许的标识符白名单。
</Callout>

## 本地演示：参数绑定防御回归

运行环境：Node.js 22.13 或更高版本。该版本可以直接使用内置的 `node:sqlite`。

<LabDownload file="sql-binding-check.mjs" label="下载完整防御检查脚本" />

新建工作目录，将下载文件保存到该目录后运行。

```bash
mkdir training-lab
cd training-lab
# 将下载的 sql-binding-check.mjs 放在当前目录
node sql-binding-check.mjs
```

预期输出包含：

```text
PASS 普通值精确匹配
PASS 单引号作为普通数据保存与查询
PASS 分号作为普通数据保存与查询
PASS 未登记值返回空结果
PASS 标识符映射与数量边界
完成：5 组防御检查通过
```

脚本在内存 SQLite 中使用虚构联系人数据，验证引号与分号保持数据语义、未登记值返回空结果、未知排序键和越界数量被拒绝。成功判据为五组 PASS 且进程退出码为 0；断言失败会报告对应检查。运行结束自动关闭数据库。

这个脚本只证明防御路径成立。要看见同一输入在拼接查询里的不同结果，在项目根目录再运行：

```bash
node examples/sql-injection-demo.mjs
```

预期：

```text
脆弱查询： SELECT username, role FROM users WHERE username = 'admin' --' AND password = 'wrong-password'
脆弱结果： {"username":"admin","role":"admin"}
参数化结果： null
合法结果： {"username":"alice","role":"user"}
```

数据库只在当前进程的内存里，不连网络，也不写磁盘。`admin' --` 在这条 SQLite 语句里注释掉了密码条件，所以错误密码仍返回 admin。参数化查询把这串字符当成用户名本身，查不到行，结果是 `null`。合法用户名和正确密码仍能查到 alice。

## 常见错误与边界

- **把“转义”当成完成修复。** 主防线是结构绑定。
- **忽略动态标识符。** `ORDER BY`、表名通常不能参数化，需要白名单。
- **只测登录框。** 搜索、导出、后台筛选同样常见。
- **数据库账号权限过大。** 注入影响随权限扩大。
- **错误信息过详。** 详细报错会把探测成本降到接近零。
