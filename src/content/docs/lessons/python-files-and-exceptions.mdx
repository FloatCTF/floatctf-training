## 引导问题：把那条管道写成 Python

第 3 课用一条管道统计了日志里每个 IP 的访问次数。第 8 课用字典做了同样的统计，但 IP 是手写在代码里的。

现在把两者接起来：让 Python 自己去读 `access.log`。这需要一个新能力，读文件。而一旦涉及文件，程序就可能遇到自己控制不了的情况：文件不在、内容格式不对。所以这一课的另一半是处理错误。

### 2. with open：打开，用完自动关

<CodeFile file="labs/python-files-and-exceptions/read_log.py" />

<TerminalSession
  title="读出所有行"
  steps={[
    {
      cmd: 'python3 read_log.py',
      out: '20\n192.0.2.10 - - [01/Oct/2026:09:12:01 +0800] "GET / HTTP/1.1" 200 5123\n\n192.0.2.10 - - [01/Oct/2026:09:12:01 +0800] "GET / HTTP/1.1" 200 5123',
      note: '第一次打印后面多了一个空行，第二次没有。',
    },
  ]}
/>

- `open("access.log")` 打开文件，得到一个**文件对象**。
- `with … as f:` 把文件对象绑到名字 f 上。缩进块结束时，文件会被自动关闭，不管中间有没有出错。
- `f.readlines()` 把所有行读成一个列表，每个元素是一行。

多出来的空行说明了一件事：读进来的每一行**末尾都带着换行符**。`print` 自己还会再加一个换行，于是空了一行。第 9 课说过读入的行几乎总要先 `strip()`，原因就在这里。

在交互模式里看得更清楚：

<TerminalSession
  title="一行的真实内容"
  environment="PYTHON 交互模式"
  prompt=">>>"
  steps={[
    { cmd: 'f = open("access.log")' },
    { cmd: 'first = f.readline()', note: 'readline 只读一行。' },
    { cmd: 'first', out: '\'192.0.2.10 - - [01/Oct/2026:09:12:01 +0800] "GET / HTTP/1.1" 200 5123\\n\'', note: '末尾的 \\n 就是换行符。' },
    { cmd: 'f.close()', note: '不用 with 的话，要自己关。' },

    { cmd: 'open("access.log", "rb").read(10)', out: "b'192.0.2.10'", note: '模式里加 b 是二进制模式，得到 bytes。读图片、压缩包这类非文字文件时用它。' },
  ]}
/>

## 二、读懂 Traceback

### 1. 多层调用时的报错

前几课见到的 Traceback 只有一段。函数调用函数时，它会变长：

<CodeFile file="labs/python-files-and-exceptions/crash.py" />

<TerminalSession
  title="三段 File，一层套一层"
  steps={[
    {
      cmd: 'python3 crash.py',
      out: '200\nTraceback (most recent call last):\n  File "/home/kali/lab/python/crash.py", line 9, in <module>\n    main()\n    ~~~~^^\n  File "/home/kali/lab/python/crash.py", line 7, in main\n    print(parse_status("broken line"))\n          ~~~~~~~~~~~~^^^^^^^^^^^^^^^\n  File "/home/kali/lab/python/crash.py", line 3, in parse_status\n    return int(parts[8])\n               ~~~~~^^^\nIndexError: list index out of range',
    },
  ]}
/>

第一行的 `200` 说明第一次调用是成功的，出错的是第二次。

<DataTable
  caption="从下往上读这份 Traceback"
  headers={["顺序", "内容", "读出什么"]}
  rows={[
    ["1", "IndexError: list index out of range", "错误类型：下标越界"],
    ["2", "line 3, in parse_status：return int(parts[8])", "直接出错的行。波浪线标在 parts[8] 上：parts 没有第 8 个元素"],
    ["3", "line 7, in main：print(parse_status(\"broken line\"))", "谁调用的它，传了什么：传进去的是 \"broken line\"，切开只有两段"],
    ["4", "line 9, in <module>：main()", "最外层：脚本的第 9 行调用了 main"],
  ]}
  columnRatios={[0.5, 2.6, 2.4]}
/>

第一行的 `most recent call last` 说的就是这个排列顺序：最近发生的调用排在最后。（来源：[Errors and Exceptions](#source-py-errors)）

读 Traceback 的三步：

1. 看最后一行，知道是哪一类错。
2. 看它上面那一段，找到直接出错的行。
3. 再往上看调用链，找出是哪里传来了有问题的数据。出错的行不一定是该改的行，这里该处理的是第 7 行传进来的那条不合格的日志。

### 2. 常见的四种异常

Python 把运行时的错误叫**异常**（exception）。每种异常有自己的名字，名字本身就在说明出了什么事。

## 三、用 try 和 except 处理错误

### 1. 接住一个异常

没人处理的异常会让程序立刻终止并打印 Traceback。有些错误是可以预见的：用户输入的不是数字，文件名打错了。对这类错误，可以提前写好「出了这种错该怎么办」。

<CodeFile file="labs/python-files-and-exceptions/safe_number.py" />

逐行走一遍，注意第 4 行有没有被执行：

<CodeStepper
  client:visible
  trace={tryTrace}
  view="values"
  title="异常发生后，执行流跳到哪里"
  intro="高亮行从第 3 行直接跳到第 5 行。第 4 行被跳过了。"
/>

<TerminalSession
  title="运行验证"
  steps={[
    { cmd: 'python3 safe_number.py', out: 'not a number: abc\ndone' },
  ]}
/>

规则是：先执行 `try` 块；一旦某一行抛出异常，`try` 块里剩下的代码全部跳过，Python 去找类型匹配的 `except`；找到就执行它，然后从整个 try 语句后面继续。没有发生异常时，`except` 块被跳过。（来源：[Errors and Exceptions](#source-py-errors)）

### 2. 输错了就再问一次

<CodeFile file="labs/python-files-and-exceptions/ask_port.py" />

<TerminalSession
  title="直到输入的是数字为止"
  steps={[
    {
      cmd: 'python3 ask_port.py',
      stdin: ['abc', '8080'],
      out: 'port: abc\nplease enter a number\nport: 8080\nok: 8080',
    },
  ]}
/>

`while True` 是一个条件永远成立的循环，靠里面的 `break` 结束。输入不是数字时，`except` 块打印提示并 `continue`，回到循环开头重新问；输入合格时，执行到 `break` 跳出。第 5 课的 `age.py` 遇到 `eighteen` 会直接崩溃，现在你知道怎么修了。

### 3. 文件不存在时给一句人话

<CodeFile file="labs/python-files-and-exceptions/open_missing.py" />

<TerminalSession
  title="同一个脚本，文件在与不在"
  steps={[
    { cmd: 'python3 open_missing.py', stdin: ['access.log'], out: 'file: access.log\n20 lines' },
    { cmd: 'python3 open_missing.py', stdin: ['nosuch.log'], out: 'file: nosuch.log\nno such file: nosuch.log', note: '没有 Traceback，程序正常结束。' },
  ]}
/>

<Callout variant="warning" title="只接你知道怎么处理的异常">
`except` 后面要写明具体的异常类型。只写一个光秃秃的 `except:` 会把所有错误都吞掉，包括你写错变量名这种本该立刻暴露的 bug，程序看起来在运行，结果却是错的。接住之后至少要打印一句说明，不要用空的 except 块把错误藏起来。
</Callout>

边界：`try` 和 `except` 处理的是运行时的异常。缩进错、括号不配对这类语法错误发生在程序开始执行之前，接不住，只能改代码。

<CheatSheet
  title="本课速查"
  items={[
    { term: 'with open("f") as f:', description: '打开文件读，缩进块结束时自动关闭。' },

    { term: 'f.read() / f.readlines()', description: '读成一个字符串 / 读成行的列表。' },
    { term: 'open("f", "w") / "a" / "rb"', description: '覆盖写 / 追加 / 二进制读。' },
    { term: 'f.write("文字\\n")', description: '写入。换行要自己加。' },
    { term: 'Traceback', description: '从最后一行往上读：错误类型，直接出错的行，调用链。' },
    { term: 'try: … except ValueError: …', description: '接住指定类型的异常。' },
    { term: 'while True: … break', description: '循环到满足条件为止。' },
    { term: 'ValueError / IndexError', description: '值不合适 / 下标越界。' },
    { term: 'KeyError / FileNotFoundError', description: '字典里没有这个键 / 文件不存在。' },
  ]}
/>

<KeyTakeaway>
读文件用 `with open(...) as f` 加 `for line in f`，每行先 `strip()` 再处理；写文件分清 `"w"` 覆盖和 `"a"` 追加。报错从最后一行读起，再顺着调用链往上找原因。能预见的错误用 `try` 和 `except` 接住并给出提示，只接明确知道怎么处理的类型。
</KeyTakeaway>
