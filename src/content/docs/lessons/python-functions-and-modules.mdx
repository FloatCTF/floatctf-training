## 引导问题：print()、len()、input() 是什么

前两课一直在用 `print()`、`len()`、`int()`、`input()`。它们的共同点是：名字后面跟一对括号，括号里放进一些值，然后得到一个结果或完成一件事。这样的东西叫**函数**。

这些函数是 Python 自带的。这一课学三件事：自己定义函数，使用放在别的文件里的函数，以及安装别人发布的函数库。

## 一、定义函数、参数与返回值

### 1. def：给一段代码起名字

- `def greet(name):` 定义一个叫 greet 的函数。括号里的 `name` 是**参数**：调用时传进来的值会绑到这个名字上。
- 缩进的部分是**函数体**。定义函数时函数体不会执行，调用时才执行。
- `greet("kali")` 是**调用**：把 `"kali"` 传给参数 name，然后执行函数体。

### 4. 函数里的名字只在函数里有效

<CodeFile file="labs/python-functions-and-modules/scope.py" />

<TerminalSession
  title="函数里把 count 设成 0，外面的 count 不受影响"
  steps={[
    { cmd: 'python3 scope.py', out: 'inside: 0\noutside: 5' },
  ]}
/>

每次调用函数，Python 都为它新开一块存放名字的空间。函数里赋值的名字都放在这块空间里，叫**局部变量**；函数外面的叫**全局变量**。`reset()` 里的 `count = 0` 新建的是一个局部的 count，函数结束后就没了，全局的 count 始终是 5。（来源：[More Control Flow Tools](#source-py-controlflow)、[Execution model](#source-py-executionmodel)）

这个规则带来的好处是：函数内部怎么命名都不会意外改掉外面的东西。函数和外界交换数据的正路只有两条，参数进，return 出。

## 二、模块：用别人的代码，拆自己的代码

### 1. import 标准库

Python 自带了大量现成的函数，按用途分装在一个个**模块**里，统称标准库。用之前先 `import`：

<TerminalSession
  title="三个标准库模块"
  environment="PYTHON 交互模式"
  prompt=">>>"
  steps={[
    { cmd: 'import math' },
    { cmd: 'math.sqrt(16)', out: '4.0', note: '模块名.函数名。sqrt 是平方根。' },

    { cmd: 'import hashlib' },
    { cmd: 'hashlib.sha256(b"kali").hexdigest()', out: "'fc5669b52ce4e283ad1d5d182de88ff9faec6672bace84ac2ce4c083f54fe2bc'", note: '第 1 课校验镜像用的 SHA256，Python 里一行就能算。b"kali" 前面的 b 表示字节，后面的课讲。' },
    { cmd: 'from base64 import b64encode', note: '另一种写法：只把模块里的某一个名字拿进来，之后用的时候不用再写模块名。' },
    { cmd: 'b64encode(b"hello")', out: "b'aGVsbG8='", note: '第 4 课的 Base64。' },
  ]}
/>

（来源：[math](#source-py-math)、[hashlib](#source-py-hashlib)、[base64](#source-py-base64)）

### 2. 自己的文件也是模块

一个 `.py` 文件就是一个模块，模块名是文件名去掉 `.py`。`checks.py` 里的函数可以被同一目录下的其他脚本导入使用：

<CodeFile file="labs/python-functions-and-modules/main.py" />

<TerminalSession
  title="main.py 用的是 checks.py 里的函数"
  steps={[
    { cmd: 'python3 main.py', stdin: ['kali-2026-ok'], out: 'password: kali-2026-ok\nok' },
    { cmd: 'python3 main.py', stdin: ['abc'], out: 'password: abc\ntoo short' },
  ]}
/>

（来源：[Modules](#source-py-modules)）

注意运行 `main.py` 时，`checks.py` 最后那三行 `print` 没有执行。原因在这一行：

```text
if __name__ == "__main__":
```

每个模块里都有一个现成的变量 `__name__`。直接运行这个文件时，它的值是 `"__main__"`；被别的文件 import 时，它的值是模块名：

<TerminalSession
  title="被导入时 __name__ 是模块名"
  environment="PYTHON 交互模式"
  prompt=">>>"
  steps={[
    { cmd: 'import checks', note: '在 ~/lab/python 目录里启动 python3，才能找到 checks。' },
    { cmd: 'checks.is_strong("kali123")', out: 'False' },
    { cmd: 'checks.is_strong("kali123", 6)', out: 'True' },
    { cmd: 'checks.__name__', out: "'checks'" },
  ]}
/>

所以写在 `if __name__ == "__main__":` 下面的代码，只在这个文件被直接运行时执行。常见的用法是把测试用的调用放在这里：单独运行时自测，被导入时保持安静。

## 三、虚拟环境与 pip

### 1. 在 Kali 上直接 pip install 会被拒绝

标准库之外，还有大量别人发布的包，用 `pip` 安装。但在 Kali 上直接装会看到这样一大段：

原因是 Kali 自带的很多工具本身就是 Python 程序，它们依赖的包由 apt 统一管理。pip 再往同一个地方装东西，可能把这些工具弄坏。报错里给了三条出路：系统里有的包用 `apt install python3-包名`；自己的项目用**虚拟环境**；独立的命令行工具用 `pipx`。（来源：[Pip install and Python's externally managed](#source-kali-pip)）

<Callout variant="danger" title="不要加 --break-system-packages">
报错最后提到可以用 `--break-system-packages` 强行安装。网上很多教程也这么教。这个选项的名字已经说明了后果，别用。
</Callout>

### 2. 虚拟环境：项目自己的一份 Python

**虚拟环境**是项目目录里的一个文件夹，里面有一份独立的 Python 和 pip。在里面装的包只属于这个项目，和系统互不影响。（来源：[Virtual Environments and Packages](#source-py-venv)）

<KeyTakeaway>
函数是有名字的一段代码：参数把值带进去，return 把结果带出来，函数里的名字不会影响外面。一个 .py 文件就是一个模块，import 之后用点号访问里面的东西。在 Kali 上装第三方包，先建虚拟环境并激活，再用 pip。
</KeyTakeaway>
