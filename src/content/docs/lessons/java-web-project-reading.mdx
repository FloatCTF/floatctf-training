## 引导问题：从哪个文件开始读

打开一个 Java 项目，往往是一层套一层的目录，最里面才是 `.java` 文件。逐个文件从头读到尾，读不完，也串不起来。

换个问法会好得多：浏览器访问 `/notes`，服务器执行的是哪个方法？顺着这个问题，只需要找到四样东西：程序从哪里启动，路径在哪里登记，谁处理这个路径，数据存在哪里。

所有 Maven 项目都是这个结构，所以拿到一个陌生项目，源码一定在 `src/main/java` 下面。（来源：[Introduction to the Standard Directory Layout](#source-mv-layout)）

## 三、换成框架以后

真实项目很少直接用 HttpServer，常见的是 Spring 这样的框架。写法不同，要找的还是那四样东西。下面是 Spring 官方入门指南里的控制器（只摘了关键部分）：

```java title="GreetingController.java（摘自 Spring 官方指南）"
@RestController
public class GreetingController {

	@GetMapping("/greeting")
	public Greeting greeting(@RequestParam(defaultValue = "World") String name) {
		return new Greeting(counter.incrementAndGet(), template.formatted(name));
	}
}
```

<DataTable
  caption="同一件事的两种写法"
  headers={["要找的", "本课的 notes 项目", "Spring 项目"]}
  rows={[
    ["处理请求的类", "implements HttpHandler", "类上标着 @RestController"],
    ["路由", "createContext(\"/notes\", ...) 集中写在 App 里", "写在每个方法头上：@GetMapping(\"/greeting\")"],
    ["按方法区分", "handle 里自己 if 判断 GET、POST", "@GetMapping、@PostMapping、@DeleteMapping 分别标在不同方法上"],
    ["取查询参数", "自己从 getQuery() 里截取", "@RequestParam 自动把 name 参数的值交给方法，没有时用 defaultValue"],
    ["怎么找路由", "grep -rn createContext src", "grep -rn '@GetMapping\\|@PostMapping\\|@RequestMapping' src"],
  ]}
  columnRatios={[1.2, 2.2, 2.6]}
/>

以 `@` 开头的叫**注解**，是贴在类和方法上的标记，框架启动时读取它们，自动完成本课 App 里手写的那些登记工作。所以读 Spring 项目时，路由不在一个集中的地方，而是散在各个控制器的方法头上，用 grep 搜注解最快。（来源：[Building a RESTful Web Service](#source-sp-rest)、[Mapping Requests](#source-sp-requestmapping)）

Maven 项目的源码在 src/main/java，目录层次就是包名；pom.xml 写着项目坐标、依赖和构建方式，mvn package 把代码编译打包进 target 里的 jar。读 Web 项目按入口、路由、处理者、数据的顺序：找到 main，找到路径登记在哪里，顺着找到处理者的方法，再看它调用的数据层。框架把路由写成方法上的注解，找法不变。读异常栈时先看第一行的原因，再找第一行属于项目自己包名的 at。
</KeyTakeaway>
