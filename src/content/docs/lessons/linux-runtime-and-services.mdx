## 引导问题：两个同时跑的程序，指针地址几乎一样，为什么没打架

开两个终端，同时跑同一个 C 程序，打印出来的栈变量地址往往都是 `0x7ffc...` 开头。它们互不覆盖，是因为每个进程看到的都不是真实物理内存，而是内核分给它的**独立虚拟地址空间**。

同样，C 代码里只写了一句 `fopen("/etc/hostname", "r")`，权限检查是在哪儿发生的？真正去摸磁盘的不是你的代码，而是**Linux 内核**。

## 二、用户态、内核态与 `strace` 系统调用追踪

Linux 把权限划成**用户态（User Space）**和**内核态（Kernel Space）**。普通程序跑在用户态，不能直接碰硬盘扇区或网卡寄存器；凡是打开文件、往终端写字、建网络连接、拉起子进程，都得向内核发一次**系统调用（System Call）**（来源：[syscalls(2)](#source-linux-syscalls-2)）。

<SyscallBoundaryDiagram />

不用去啃内核源码，学会 **`strace`** 就能把程序发出的每次系统调用原样打印出来（来源：[strace(1)](#source-linux-strace-1)）：

## 三、环境变量、动态链接器与生产服务单元

### 1. 环境变量与加载边界

（来源：[environ(7)](#source-linux-environ-7)、[ld.so(8)](#source-linux-ld-so-8)）

- **`PATH` 查找顺序**：敲 `python3` 时，shell 按 `$PATH` 从左往右查找同名可执行文件；平时用 `command -v python3`（可同时区分 shell 别名、内建命令与外部文件）和 `echo "$PATH"` 核实。写脚本或定时任务时直接写绝对路径（如 `/usr/bin/python3`），避免被前面目录的同名文件拦截。
- **环境变量的保密边界**：传 `APP_MODE=staging` 这类普通开关很顺手，但它会继承给子进程，且进程的初始环境记录在 `/proc/<pid>/environ`（受 `ptrace` 权限检查 `PTRACE_MODE_READ_FSCREDS` 约束，默认配置下同用户通常可读，在部分安全加固策略下也可能被拒绝）。因此不要在日志或调试页倾倒环境变量；线上存放敏感密钥优先使用专门的凭据机制。
- **`LD_PRELOAD` 与安全执行模式**：动态链接器 `ld.so` 允许普通进程靠 `LD_PRELOAD` 抢先加载自定义 `.so` 共享库，常用来做调试和性能分析。遇到带 `setuid`/`setgid` 或特殊文件能力的程序时，按 [ld.so(8)](#source-linux-ld-so-8) 会进入安全执行模式：带路径斜杠（`/`）的条目直接忽略，只允许从标准搜索目录加载同样带 `setuid` 位的预加载库，挡住普通用户随意劫持提权程序。

<KeyTakeaway>
每个进程运行在内核隔离的虚拟地址空间中：在本课默认 x86-64 PIE 布局里，代码段为 r-xp，数据、堆与栈默认为 rw-p（权限分离，具体匿名映射仍取决于 mmap 标志）。文件与 I/O 操作都必须经系统调用交由内核裁决。结合 /proc/maps、readelf -d、ldd（仅可信程序）与 strace 排查运行时，再配合独立服务账号和 LoadCredential 文件凭据，就能把代码行为和系统运行接起来。
</KeyTakeaway>
