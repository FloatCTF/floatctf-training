## 引导问题：为什么两个同时运行的程序，变量地址长得差不多却不会互相覆盖

你同时打开两个终端，都跑同一个 C 程序，打印出来的指针地址可能都是 `0x7ffc...`。它们没有打架，是因为每个进程看到的都是内核给它分配的**独立虚拟地址空间**；同样，你的程序只是调用了一句 `fopen("/etc/hostname", "r")`，为什么就能被权限系统挡住或放行？因为真正去摸磁盘的不是你的代码，而是**Linux 内核**。

## 二、用户态、内核态与 `strace` 系统调用追踪

Linux 把 CPU 权限切成了**用户态（User Space）**和**内核态（Kernel Space）**。普通程序跑在用户态，不能直接读写硬盘扇区或网卡寄存器；凡是打开文件、打印到屏幕、建网络连接、创建子进程，都必须向内核发起一次**系统调用（System Call）**（来源：[syscalls(2)](#source-linux-syscalls-2)）。

你不需要读懂内核源码，学会用 **`strace`** 就能把任意程序的系统调用像 X 光片一样拍出来（来源：[strace(1)](#source-linux-strace-1)）：

## 三、环境变量、动态链接器与生产服务单元

### 1. 环境变量与加载边界

（来源：[environ(7)](#source-linux-environ-7)、[ld.so(8)](#source-linux-ld-so-8)）

- **`PATH` 顺序**：终端敲 `python3` 时，shell 会按 `$PATH` 从左到右依次查找第一个同名可执行文件（可用 `echo "$PATH"` 和 `which python3` 核实）。写脚本或定时任务时，用绝对路径（如 `/usr/bin/python3`）可以避免被前面目录里的同名文件劫持。
- **配置注入边界**：环境变量适合传递非敏感运行参数（如 `APP_MODE=staging`），但会被子进程继承，且同用户进程可读 `/proc/<pid>/environ`；因此既不要在调试页或日志里打印整个环境表，在生产 systemd 服务里也应优先用专门的凭据机制存放密钥。
- **`LD_PRELOAD` 与安全执行模式**：动态链接器 `ld.so` 支持用 `LD_PRELOAD` 在普通进程启动时优先加载自定义 `.so` 共享库（常用于调试和性能分析）。当程序处于安全执行模式（如带 `setuid`/`setgid` 或特定文件能力）时，按 [ld.so(8)](#source-linux-ld-so-8) 规则，动态链接器会严格受限——包含路径斜杠（`/`）的条目会被忽略，只允许从标准搜索目录加载同样带 `setuid` 位的预加载库，以防止普通用户随意劫持提权程序。

<KeyTakeaway>
进程看到的地址是内核隔离出的虚拟内存（代码 r-xp、数据/堆/匿名 mmap/栈通常 rw-p），所有文件与网络动作都要跨过系统调用边界交由内核检查；学会用 /proc/maps、readelf -d、ldd（仅可信程序）和 strace 透视进程，再掌握专用服务账号与 systemd Credentials 凭据隔离，你就真正打通了“写代码”与“看懂系统运行”的隔阂。下一课我们把磁盘上的可执行文件拆开，看懂 ELF 结构与最基本的 x86-64 汇编。
