## 一、地址、端口和连接

### 1. IP 地址：机器在哪

网络上的每台机器都有一个 **IP 地址**，用来区分彼此，相当于它在网络里的门牌号。常见的写法是用点隔开的四个数，每个数在 0 到 255 之间，例如 `192.168.1.10`。（来源：[MDN: How does the Internet work?](#source-mdn-internet)）

<TerminalSession
  title="看看自己的地址"
  steps={[
    { cmd: 'hostname -I', out: '172.17.0.2', note: '这台机器的 IP 地址。你的多半以 192.168 或 10 开头，由虚拟机软件分配。' },
    { cmd: 'ip -4 -br addr show lo', out: 'lo               UNKNOWN        127.0.0.1/8', note: 'lo 是一块特殊的「网卡」，地址是 127.0.0.1。' },
    {
      cmd: 'ping -c 3 127.0.0.1',
      out: 'PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.\n64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.048 ms\n64 bytes from 127.0.0.1: icmp_seq=2 ttl=64 time=0.063 ms\n64 bytes from 127.0.0.1: icmp_seq=3 ttl=64 time=0.056 ms\n\n--- 127.0.0.1 ping statistics ---\n3 packets transmitted, 3 received, 0% packet loss, time 2076ms\nrtt min/avg/max/mdev = 0.048/0.055/0.063/0.006 ms',
      note: 'ping 向对方发一个小报文并等它回应，用来检查「能不能到」。-c 3 表示发三个就停。time 的数字每次不同。',
    },
  ]}
/>

有三类地址要分清：

<DataTable
  caption="三类 IP 地址"
  headers={["类别", "范围", "含义"]}
  rows={[
    ["环回地址", "127.0.0.1（整个 127 开头的段）", "永远指「这台机器自己」。发往它的数据不出本机"],
    ["私有地址", "10.x.x.x、172.16.x.x 到 172.31.x.x、192.168.x.x", "只在一个内部网络里有效，例如家里、宿舍、虚拟机的网络。互联网上不认"],
    ["公网地址", "其余大部分地址", "在互联网上唯一，别人可以凭它找到这台机器"],
  ]}
  columnRatios={[0.8, 1.8, 2.2]}
/>

（来源：[RFC 1918](#source-rfc1918)、[RFC 6890](#source-rfc6890)）

`127.0.0.1` 在每台机器上都指它自己。在虚拟机里访问 `127.0.0.1`，访问的是虚拟机；在 Windows 里访问 `127.0.0.1`，访问的是 Windows。这两个不是同一台机器。

（来源：[ping(8)](#source-man-ping)）

### 2. 端口：机器上的哪个程序

一台机器上同时运行着很多会用网络的程序。数据到了这台机器，还得知道交给谁。**端口**就是用来区分程序的编号，范围是 0 到 65535。（来源：[RFC 9293](#source-rfc9293)）

一个地址加一个端口，写成 `地址:端口`，例如 `127.0.0.1:8000`，才能确定「哪台机器上的哪个程序」。

一些服务有约定俗成的端口：

<DataTable
  caption="先记住这四个"
  headers={["端口", "服务", "用途"]}
  rows={[
    ["22", "SSH", "远程登录"],
    ["53", "DNS", "把域名换成 IP 地址"],
    ["80", "HTTP", "网页"],
    ["443", "HTTPS", "加密的网页"],
  ]}
  columnRatios={[0.6, 0.8, 2]}
/>

（来源：[IANA 端口登记表](#source-iana-port-registry)）

0 到 1023 这一段留给这类系统服务，只有管理员权限的程序才能监听，所以自己练习时用 8000、9000 这样的大端口。（来源：[RFC 6335](#source-rfc6335)、[ip(7)](#source-man-ip7)）

服务器程序选定一个端口等别人来连，这叫**监听**（listen）。客户端程序发起连接时也需要一个端口，由系统临时分配一个，用完就还。

### 3. TCP：一条可靠的管道

网络本身只管把一个个小数据包往目的地送，不保证送到，也不保证先发的先到。**TCP** 在此之上提供一条**连接**：数据从一端写进去，从另一端按原来的顺序读出来，中途丢了会自动重发。对程序来说，它就像一根接在两台机器之间的管道。

建立连接需要双方来回三个报文，叫**三次握手**：

<DataTable
  caption="三次握手"
  headers={["顺序", "谁发的", "意思"]}
  rows={[
    ["1", "客户端发 SYN", "我想和你建立连接"],
    ["2", "服务器回 SYN + ACK", "收到，我也准备好了"],
    ["3", "客户端回 ACK", "收到，开始吧"],
  ]}
  columnRatios={[0.5, 1.4, 2]}
/>

握手完成之后才开始传数据。一条连接由两端的地址和端口共同确定：客户端的地址和端口，服务器的地址和端口。（来源：[RFC 9293](#source-rfc9293)）

TCP 只负责把字节送到，不关心字节的含义。管道里说什么话，由上面的协议规定。下一课的 HTTP 就是其中一种。

## 二、让两个程序隔着端口说话

这一节需要两个终端。在终端窗口里按 `Ctrl` + `Shift` + `T` 可以再开一个标签页。下面把它们叫作终端 A 和终端 B。

### 1. 在终端 A 里启动服务器

先准备一个目录和一个文件：

Python 自带一个小型的网页服务器，一条命令就能把当前目录里的文件通过网络提供出去：

<TerminalSession

      note: '8000 是要监听的端口。0.0.0.0 表示在这台机器的所有地址上监听。提示符没有回来，说明程序在运行，正在等连接。',
    },
  ]}
/>

（来源：[http.server](#source-py-http-server)）

### 2. 在终端 B 里确认它在监听

换到终端 B：

<TerminalSession
  title="终端 B：谁在监听"
  steps={[
    { cmd: 'cd ~/lab/net' },
    {
      cmd: 'ss -tln',
      out: 'State     Recv-Q    Send-Q       Local Address:Port        Peer Address:Port\nLISTEN    0         5                  0.0.0.0:8000             0.0.0.0:*',
      note: '-t 只看 TCP，-l 只看监听中的，-n 端口显示成数字。Local Address:Port 一栏的 0.0.0.0:8000 就是刚才那个服务器。你的列表里可能还有别的行。',
    },
  ]}
/>

（来源：[ss(8)](#source-man-ss)）

### 3. 连上去

<TerminalSession
  title="终端 B：用 curl 取回文件"
  steps={[
    { cmd: 'curl http://127.0.0.1:8000/hello.txt', out: 'hello from kali', note: 'curl 连上 127.0.0.1 的 8000 端口，要来了 hello.txt 的内容。' },
  ]}
/>

回头看终端 A，多了一行日志，记着是谁、在什么时候、要了什么、结果如何：

```text
127.0.0.1 - - [01/Oct/2026 16:32:30] "GET /hello.txt HTTP/1.1" 200 -
```

这种日志的格式你在第 3 课就见过。当时分析的 `access.log`，就是服务器这样一行一行记下来的。

### 4. 不用 curl，自己和服务器说话

`curl` 替你做了两件事：建立 TCP 连接，再按 HTTP 的规矩说话。现在把第二件事拿回来自己做。

`nc` 只做第一件事：连上指定的地址和端口，之后你敲什么它发什么，对方回什么它显示什么。

<TerminalSession
  title="终端 B：用 nc 手敲一个请求"
  steps={[
    {
      cmd: 'nc 127.0.0.1 8000',
      stdin: ['GET /hello.txt HTTP/1.0', ''],
      out: 'GET /hello.txt HTTP/1.0\n\nHTTP/1.0 200 OK\nServer: SimpleHTTP/0.6 Python/3.14.7\nDate: Thu, 01 Oct 2026 16:32:32 GMT\nContent-type: text/plain\nContent-Length: 16\nLast-Modified: Thu, 01 Oct 2026 16:32:26 GMT\n\nhello from kali',
      note: '连上之后没有任何提示。输入 GET /hello.txt HTTP/1.0，回车，再按一次回车留一个空行。前两行是你敲的，从 HTTP/1.0 200 OK 开始是服务器回的。',
    },
  ]}
/>

（来源：[nc(1)](#source-man-nc)）

你敲的那一行是一个最简单的 HTTP 请求，空行表示「我说完了」。服务器回的内容里，空行上面是关于这次响应的说明，空行下面是文件内容。这些下一课逐行讲。

这里要带走的是：**服务器和客户端之间传的是普普通通的文字，谁都可以连上去，照着规矩敲。** 浏览器和 `curl` 只是替你敲得更快。

### 5. 两种连不上

## 三、名字：DNS

### 1. 把名字换成地址

人记不住 `198.41.0.4` 这样的数字，所以给机器起了名字，叫**域名**，例如 `example.com`。但程序建立连接时只认 IP 地址。把域名换成 IP 地址的这套系统叫 **DNS**。

你的机器自己不存这份对照表。它把问题交给一台 **DNS 服务器**，由对方回答。（来源：[MDN: What is a domain name?](#source-mdn-domain-name)、[RFC 1034](#source-rfc1034)）

`dig` 是专门用来问 DNS 的工具：

<TerminalSession
  title="域名背后的地址"
  steps={[
    { cmd: 'dig +short a.root-servers.net', out: '198.41.0.4', note: '+short 只显示答案。这个地址很多年没变过。' },
    { cmd: 'dig +short example.com', out: '104.20.23.154\n172.66.147.243', note: '一个域名可以对应多个地址。地址由网站的运营方决定，会变，顺序也可能不同，你的结果不一定和这里一样。' },
    { cmd: 'grep localhost /etc/hosts', out: '127.0.0.1\tlocalhost\n::1\tlocalhost ip6-localhost ip6-loopback', note: '本机还有一份手写的对照表 /etc/hosts，系统先查它。localhost 这个名字就是在这里对应到 127.0.0.1 的。第二行是 IPv6 的写法。' },
  ]}
/>

（来源：[dig(1)](#source-man-dig)、[IANA Root Servers](#source-iana-root-servers)）

去掉 `+short` 会看到完整的应答，里面有问了什么、答了什么、问的是哪台 DNS 服务器。信息很多，初学时用 `+short` 就够。

### 3. 四步串起来

回到引导问题。`curl` 的 `-v` 选项会把它做的每一步都打印出来：

<KeyTakeaway>
访问一个网址要依次过四步：DNS 把域名换成 IP 地址，TCP 向那个地址的某个端口建立连接，客户端沿连接发出请求，服务器发回响应。IP 地址确定机器，端口确定机器上的程序，`127.0.0.1` 永远是本机。连不上时先分清卡在哪一步：名字查不到是 DNS 的事，Connection 失败是那个端口上没有程序在听。
</KeyTakeaway>
