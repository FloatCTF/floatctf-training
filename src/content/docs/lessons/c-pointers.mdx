## 引导问题：怎样让 swap 真的管用

第 21 课的 `swap(x, y)` 没能交换 `main` 的变量，因为函数拿到的是值的副本。

想让一个函数改到调用者的变量，光给它值是不够的。得告诉它：**那个变量在内存的什么位置。** 它拿着位置找过去，才改得到本尊。

「位置」就是前几课图里一直出现的地址。这一课学会把地址传来传去。

## 一、地址和指针

<DataTable

**指针**就是一个变量，它里面存的不是普通的数，而是另一个变量的地址。（来源：[CS50x: Lecture 4](#source-cs50-memory)）

最容易混的是星号，它在两个地方意思不同：

- 在**声明**里，`int *p` 的星号说明「p 是指针」。
- 在**语句**里，`*p` 的星号是一个动作：到 p 指的地方去。这个动作叫**解引用**。

第 10 行 `*p = 99;` 没有碰 `p` 本身。它顺着 `p` 找到了 `x`，把 99 写了进去。所以最后打印 `x` 是 99。（来源：[N1570](#source-n1570)、[Beej's Guide: Pointers](#source-beej-pointers)）

### 2. 指针自己也是变量

指针有自己的地址，也占内存。在这台 64 位的机器上，任何类型的指针都占 8 个字节，因为地址是一个 64 位的数。`int *` 和 `char *` 的区别不在大小，而在于解引用时「到那里取几个字节、当成什么类型」。

第三条解释了上一课的越界：`codes[3]` 就是 `*(codes + 3)`，一次指针运算加一次解引用，没有任何环节会去检查 3 是否超出了数组。

第一条解释了为什么把数组传给函数时必须另外传长度：函数收到的只是第 0 个元素的地址，一个指针，里面没有长度信息。

## 三、指针出错的三种样子

指针让你能访问任意地址。地址错了，C 不会拦你。

### 1. 空指针

`NULL` 是一个特殊的指针值，表示「不指向任何东西」。对它解引用：

<CodeFile file="labs/c-pointers/null.c" mark="4,6" />

<TerminalSession
  title="顺着一个哪也不指的指针去取值"
  steps={[
    { cmd: 'gcc -Wall null.c -o null' },
    { cmd: './null', out: 'before\nzsh: segmentation fault  ./null', note: '第 5 行正常执行了，第 6 行解引用空指针时被系统终止，第 7 行没有机会执行。' },
    { cmd: 'echo $?', out: '139' },
  ]}
/>

`NULL` 的数值是 0。地址 0 附近的内存，系统不允许任何程序访问，一碰就是段错误。这其实是最「友好」的一种指针错误：它立刻崩溃，而且崩在出错的那一行。（来源：[N1570](#source-n1570)、[signal(7)](#source-man-signal7)）

### 2. 指向已经消失的局部变量

<CodeFile file="labs/c-pointers/dangling.c" mark="3-6" note="make 返回了自己局部变量的地址。" />

<TerminalSession
  title="编译器已经看出来了"
  steps={[
    {
      cmd: 'gcc dangling.c -o dangling',
      out: 'dangling.c: In function ‘make’:\ndangling.c:5:12: warning: function returns address of local variable [-Wreturn-local-addr]\n    5 |     return &value;\n      |            ^~~~~~',
      note: '不加 -Wall 也会警告。',
    },
    { cmd: './dangling', out: 'zsh: segmentation fault  ./dangling' },
  ]}
/>

第 21 课讲过，函数返回时它的栈帧就作废了。`value` 是 `make` 的局部变量，`make` 一返回，`value` 所在的那块内存就不再属于它。把这个地址交出去，调用者拿到的是一个指向「已经不存在的变量」的指针，叫**悬垂指针**。

这个版本的 gcc 发现之后，干脆让函数返回了空指针，所以程序崩得很干脆。在别的编译器上，它可能返回那个旧地址，程序读到的是下一次函数调用留在那里的随便什么东西，不崩溃，只是结果莫名其妙。（来源：[N1570](#source-n1570)）

### 3. 没有初始化的指针

第 21 课说过，局部变量不赋初值时，里面是内存里原来留下的内容。指针也是变量。`int *p;` 之后直接 `*p = 5;`，是往一个随机的地址写数据。运气好是段错误，运气不好是悄悄改掉了程序里别的变量。

<DataTable
  caption="三种指针错误"
  headers={["名字", "指针里的值", "解引用时", "怎样避免"]}
  rows={[
    ["空指针", "NULL，也就是 0", "立刻段错误", "解引用之前检查 if (p != NULL)"],

    ["野指针", "从未赋值，是随机的", "未定义：可能崩溃，可能改坏别的数据", "声明指针时就赋初值，没有目标就赋 NULL"],

<KeyTakeaway>
指针是存着地址的变量。`&x` 取 x 的地址，`*p` 顺着地址找到那块内存。把地址传给函数，函数就能改到调用者的变量，`scanf` 和修好的 `swap` 都是这样工作的。数组名是第 0 个元素的地址，`a[i]` 就是 `*(a + i)`，指针加一往后挪一个元素。C 不检查指针里的地址是否有效：空指针、已消失的局部变量的地址、从未赋值的指针，解引用它们都是未定义行为。
</KeyTakeaway>
