## 引导问题：拿到一个陌生 Web 项目，怎么从一条请求追到关键源码

学校练习通常只给几十行单一文件；真正接手开源仓库或准备做代码审计时，面前往往是几十上百个文件、反代配置和一句含糊的接口报错。

面对陌生代码库，顺着一条请求从外部进入系统的路径往里追最稳妥：先标出数据跨越了哪些**信任边界**，再明确合法动手范围，最后用确定性搜索命令配合 AI 定位到具体行号并用终端实跑验证。

### 2. 法律底线与课程授权规范

技术本身中性，但测谁、怎么测决定了合不合规。下面把**法律明文规范**和**本课程的实验纪律**分开写清（来源：[《中华人民共和国网络安全法》](#source-prc-cybersecurity-law)）：

- **法律明确规范**：修订后的《中华人民共和国网络安全法》（2025 年 12 月 29 日公布）**第二十九条**规定，任何个人和组织**不得从事非法侵入他人网络、干扰他人网络正常功能、窃取网络数据等危害网络安全的活动**，也不得提供专门用于从事上述活动的程序、工具，或明知他人从事上述活动而为其提供技术支持等帮助；同时**第二十八条**及其他适用规定对向社会发布系统漏洞等网络安全信息设有明确合规要求，不得违反规定擅自公开扩散。
- **本课程的授权纪律**：为了避免边界不清时干扰正常业务或踩线，本课程统一要求**先取得明确授权并划定测试范围**（商业或校内项目里应留有可追溯的书面或工单确认）。

<Callout variant="warning" title="本课程的三条实操底线">
1. **不对未获明确授权的外部系统动手**：学校网站、公网业务、他人服务器——不顺手扫目录、不试着改 `uid=` 看别人资料、不改包重放，避免触发未授权访问、干扰服务正常功能或法律风险。
2. **只留在三个合规场地练习**：自己的本机 `127.0.0.1` / Docker 环境、公开 CTF 靶场与正规演练平台、或明确约定资产范围的授权项目（如正式 SRC 平台公布的测试范围）。
3. **不拉取、不传播非授权数据**：偶然发现公开隐患时，通过目标方官方安全响应通道及适用主管机关报告，绝不拖库，也不违反规定向社会扩散利用细节。
</Callout>
