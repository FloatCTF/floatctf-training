## 引导问题：同样学完基础，为什么有人面对陌生项目能迅速抓到重点

学校课程习惯给你一份写好题干的几十行作业；真实世界和下学期的 Web 安全实战刚好相反——丢到你面前的往往是一个几百上千行的陌生项目、一套带反代的容器环境，或者一句语焉不详的报错。

光靠背零散命令很快就会撞墙。真正拉开差距的是三件事：**用「信任边界」看系统、守住法律与授权底线、以及有一套结合命令行与 AI 的确定性读码流程**。

### 2. 法律底线与课程授权规范

安全技术本身是中性的，但实施对象与行为边界决定了合规与否。我们把**法律条文本身**和**本课程的实验规范**分开写清，既不歪曲法条，也不放松底线（来源：[《中华人民共和国网络安全法》](#source-prc-cybersecurity-law)）：

- **法律明确禁止的行为**：修订后的《中华人民共和国网络安全法》明确规定，任何个人和组织**不得从事非法侵入他人网络、干扰他人网络正常功能、窃取网络数据等危害网络安全的活动**；也不得提供专门用于从事侵入网络、干扰网络正常功能及防护措施、窃取网络数据等危害网络安全活动的程序、工具，或明知他人从事上述活动而为其提供技术支持等帮助。
- **本课程的授权与测试范围规范**：为避免初学者在边界不清时干扰真实业务或误触法律红线，本课程统一要求**先取得明确授权并界定测试范围**（商业或校内项目实践中通常保留可追溯的书面/工单确认）。

<Callout type="warning" title="本课程的三条实操底线">
1. **不对未获明确授权的外部系统做探测与测试**：学校网站、公网业务、他人服务器——不顺手跑目录扫描、不试探越权参数 `uid=`、不做改包重放，避免触发未授权访问、干扰服务正常功能或法律风险。
2. **只留在三个合规场地练手**：你自己的本地 `127.0.0.1` / Docker 环境、公开 CTF 靶场与合规演练平台、或明确约定资产范围的授权测试项目（如正式 SRC 平台公布的测试范围）。
3. **不拉取、不传播非授权数据**：遇到意外发现的公开安全隐患，遵循负责任披露通道向官方应急响应中心报告，绝不拉取数据或公开扩散利用方法。
</Callout>

<KeyTakeaway>
安全的核心视角是识别每一处「信任边界」，行为的底线是严格遵守法律对非法侵入、干扰服务与窃取数据的禁令并坚持本课程「仅测试明确授权目标」的纪律；面对陌生代码库，先用命令行定位入口、配置和外部输入流，再把 AI 当成高效的解释与初筛助手，并坚持用源码行号和真实运行结果验证每一条结论。下一课我们用一场涵盖五关的本地综合前哨实战，给整个基础学期画上句号。
