## 引导问题：一个最小的网站要哪几样东西

一个留言板看起来简单：一个表单，一列留言。真把它做出来，要回答的问题不少：数据存在哪？用户提交的文字怎么存、怎么显示才安全？提交之后刷新页面会不会重复提交？代码怎么保存历史？换一台机器怎么跑起来？

这些问题这学期都分别学过。这节课把它们放进同一个项目里。

`post.php` 里每一段都有用处：

- **只接受 POST**：直接在地址栏打开 post.php 是 GET 请求，回 405。
- **服务器端校验**：表单上的 `required`、`maxlength` 只约束浏览器，不经过表单直接发请求（比如用 curl）就绕开了，所以服务器必须再查一遍。`iconv_strlen` 按字符数计算，一个汉字算一个。（来源：[Client-side form validation](#source-mdn-form-validation)、[iconv_strlen](#source-php-iconv-strlen)）
- **预处理语句**：SQL 里只有问号，名字和留言作为参数单独交给数据库，里面有引号也只是数据。（来源：[Prepared statements](#source-php-pdo-prepared)）
- **303 跳转**：存好之后回 303 和 `Location: index.php`，浏览器接着用 GET 打开首页。这叫 Post/Redirect/Get：用户刷新的是首页，不会把同一条留言再提交一次。（来源：[RFC 9110 §15.4.4](#source-rfc9110)、[header](#source-php-header)）

最后两条值得多看一眼：同一段文字，在数据库里是 `<b>not bold</b>`，在网页里是 `&lt;b&gt;not bold&lt;/b&gt;`。存的时候保持原样，输出到哪里就按哪里的规则处理：放进 SQL 用预处理语句，放进 HTML 用 `htmlspecialchars`。（来源：[htmlspecialchars](#source-php-htmlspecialchars)）

<KeyTakeaway>
一个最小的网站也要处理好三件事：用户提交的数据在服务器端重新校验，写进数据库用预处理语句，输出到 HTML 前用 htmlspecialchars 转义；数据库里存原文，到了哪里就按哪里的规则处理。表单提交后用 303 跳回首页，刷新不会重复提交。用 Git 按「每次都是能用的状态」分步提交，数据文件用 .gitignore 排除。Dockerfile 只复制程序，compose.yaml 把数据放进卷，任何人拿到仓库一条命令就能部署。
</KeyTakeaway>
