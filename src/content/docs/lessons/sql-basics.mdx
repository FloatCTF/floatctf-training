## 引导问题：登录的时候，网站在查什么

你在登录框里输入用户名和密码，点提交。第 14 课的练习站是拿一个写在代码里的字典来核对的。真实的网站有几万、几百万个用户，不可能写在代码里。

它们的做法是把用户存在**数据库**里，登录时向数据库提一个问题：「有没有名字是这个、密码对得上的用户？」数据库答有或没有。

这个问题是用一种叫 **SQL** 的语言写的。网站的几乎每一个功能，查商品、看订单、发评论，背后都是一条或几条 SQL。读得懂 SQL，才看得懂网站在后台做什么。

<Callout variant="danger" title="UPDATE 和 DELETE 一定要带 WHERE">
`UPDATE users SET city = 'Beijing';` 没有 WHERE，会把**每一行**的城市都改掉。`DELETE FROM users;` 会删光整张表。这两条都是合法的语句，数据库不会问你「确定吗」。动手之前先把同样的 WHERE 写成 SELECT 执行一遍，看清会选中哪些行。
</Callout>

（来源：[INSERT](#source-sqlite-insert)、[UPDATE](#source-sqlite-update)、[DELETE](#source-sqlite-delete)）

## 三、多表查询，以及从 Python 里查

### 1. JOIN：把编号换成名字

`orders` 表记录了谁买了什么，但它里面只有编号：

<TerminalSession
  environment="SQLITE 交互界面 · shop.db"
  prompt="sqlite>"
  title="订单表里只有数字"
  steps={[
    { cmd: 'SELECT * FROM orders;', out: '╭────┬─────────┬─────────┬──────────╮\n│ id │ user_id │ item_id │ quantity │\n╞════╪═════════╪═════════╪══════════╡\n│  1 │       1 │       1 │        1 │\n│  2 │       2 │       4 │       10 │\n│  3 │       2 │       2 │        1 │\n│  4 │       3 │       6 │        2 │\n│  5 │       3 │       4 │        3 │\n╰────┴─────────┴─────────┴──────────╯', note: 'user_id 是 users 表里的 id，item_id 是 items 表里的 id。' },
    { cmd: 'SELECT users.name, items.name, orders.quantity FROM orders JOIN users ON orders.user_id = users.id JOIN items ON orders.item_id = items.id;', out: '╭───────┬──────────┬──────────╮\n│ name  │   name   │ quantity │\n╞═══════╪══════════╪══════════╡\n│ alice │ keyboard │        1 │\n│ bob   │ sticker  │       10 │\n│ bob   │ mouse    │        1 │\n│ carol │ handbook │        2 │\n│ carol │ sticker  │        3 │\n╰───────┴──────────┴──────────╯', note: '这一条比较长，要在一行里敲完。JOIN … ON … 的意思是：把另一张表里编号对得上的那一行接到旁边。' },
    { cmd: 'SELECT users.name, SUM(items.price * orders.quantity) AS total FROM orders JOIN users ON orders.user_id = users.id JOIN items ON orders.item_id = items.id GROUP BY users.name ORDER BY total DESC;', out: '╭───────┬───────╮\n│ name  │ total │\n╞═══════╪═══════╡\n│ alice │   120 │\n│ bob   │   110 │\n│ carol │    85 │\n╰───────┴───────╯', note: '接起来之后照样可以分组统计：每个人一共花了多少。AS total 给这一列起个名字。' },
  ]}
/>

为什么不把名字直接写进订单表？因为同一份信息只该存一处。`bob` 改名时只需要改 `users` 表里的一行，所有订单查出来的名字自然跟着变。多张表之间用编号互相指向，查的时候用 JOIN 接起来，这是数据库的基本用法。

两张表都有 `name` 列，所以要写成 `users.name`、`items.name` 来区分。

### 2. UNION：把两个查询的结果摞起来

<TerminalSession
  environment="SQLITE 交互界面 · shop.db"
  prompt="sqlite>"
  title="上下拼接"
  steps={[
    { cmd: 'SELECT name, role FROM users UNION SELECT name, category FROM items;', out: '╭───────────┬──────────╮\n│   name    │   role   │\n╞═══════════╪══════════╡\n│ alice     │ admin    │\n│ bob       │ member   │\n│ carol     │ member   │\n│ dave      │ member   │\n│ handbook  │ book     │\n│ keyboard  │ hardware │\n│ mouse     │ hardware │\n│ sticker   │ merch    │\n│ t-shirt   │ merch    │\n│ usb-drive │ hardware │\n╰───────────┴──────────╯', note: '前四行来自 users，后六行来自 items。列名用的是第一个查询的。' },
    { cmd: 'SELECT name, role FROM users UNION SELECT name FROM items;', out: 'Parse error near line 2: SELECTs to the left and right of UNION do not have the same number of result columns', note: '两边的列数必须相同。这里左边两列，右边一列，所以报错。' },
  ]}
/>

JOIN 是左右拼：给每一行补上别的表里的列。UNION 是上下拼：把另一个查询的行接在下面。（来源：[SELECT](#source-sqlite-select)）

### 3. 让 Python 去查

回到引导问题。网站的程序就是这样向数据库提问的。先用 `.quit` 退出 sqlite3，回到普通的终端。

<CodeFile file="labs/sql-basics/find_user.py" mark="5" note="保存为 ~/lab/sql/find_user.py。注意第 5 行的问号。" />

<TerminalSession
  title="程序替你写 SQL"
  steps={[
    { cmd: "sqlite3 shop.db 'SELECT COUNT(*) FROM users;'", out: '╭──────────╮\n│ COUNT(*) │\n╞══════════╡\n│        4 │\n╰──────────╯', note: '顺带一提：在 shell 里也可以不进交互界面，直接问一句。' },
    { cmd: 'python3 find_user.py', setup: 'cp ~/Downloads/find_user.py .', stdin: ['alice'], out: 'name: alice\nalice is admin', note: '输入 alice 回车。' },
    { cmd: 'python3 find_user.py', stdin: ['nobody'], out: 'name: nobody\nno such user' },
    { cmd: 'python3 find_user.py', stdin: ["o'brien"], out: "name: o'brien\nno such user", note: '输入里带着一个单引号。程序没有出错，只是老老实实地去找叫 o\'brien 的人。' },
  ]}
/>

第 5 行的 SQL 里，本该写名字的地方是一个问号，名字放在后面的括号里另外交给数据库。这个问号叫**占位符**。数据库会把交来的值整个当作数据，里面有引号也好、有 SQL 关键字也好，都不会被当成语句的一部分。

<Callout variant="warning" title="不要自己把输入拼进 SQL">
另一种写法是用字符串拼接：`"… WHERE name = '" + name + "'"`。它在输入正常的名字时结果一样，但用户输入的内容会直接成为 SQL 语句的一部分，输入一个单引号就足以让语句变样。凡是把别人给的值放进 SQL，一律用占位符。
</Callout>

（来源：[sqlite3](#source-py-sqlite3)）

<KeyTakeaway>
数据库把数据存在表里，一行是一条记录，一列是一项属性。SQL 用 SELECT 查、INSERT 加、UPDATE 改、DELETE 删，WHERE 决定作用于哪些行，改和删时绝不能漏。多张表用编号互相指向，JOIN 把它们左右接起来，UNION 把两个查询上下接起来。程序向数据库提问时，别人给的值要用占位符传进去，不能拼进 SQL 字符串。
</KeyTakeaway>
