## 引导问题：登录之后，服务器怎么知道还是你

你在一个网站登录，然后点开「我的主页」。这是两次访问。上一课讲过，每次访问都是一问一答，答完就结束。

那么第二次访问时，服务器怎么知道来的还是刚才登录的那个人？它没有看见你的脸，两次访问也可能走的是两条不同的连接。

答案就写在请求和响应的文字里。这一课结束时，你会亲手把那一行找出来，并且自己带着它去访问。

### 2. 用 POST 提交用户名和密码

`GET` 的意思是「把这个东西给我」。登录是另一种动作：把一份数据交给服务器处理。这种请求用 **POST** 方法，数据放在请求的正文里。（来源：[RFC 9110](#source-rfc9110)）

练习站的账号是 `student`，密码是 `kali123`。

<TerminalSession
  title="终端 B：先错一次，再对一次"

### 3. Cookie：服务器发给你的一张号码牌

HTTP 是**无状态**的：服务器处理完一个请求就忘了，下一个请求来的时候，它不会自动知道这和上一个有什么关系。（来源：[RFC 9110](#source-rfc9110)）

要让服务器认出「还是刚才那个人」，办法是让客户端每次都出示一个记号：

<DataTable
  caption="登录之后发生的事"
  headers={["步骤", "谁做的", "做了什么"]}
  rows={[
    ["1", "服务器", "核对密码正确后，生成一个随机的会话编号，在自己这边记下「这个编号是 student」"],
    ["2", "服务器", "在响应里用 Set-Cookie 头把编号交给客户端"],
    ["3", "客户端", "把编号存起来"],
    ["4", "客户端", "之后每次请求这个站点，都用 Cookie 头把编号带上"],
    ["5", "服务器", "看到编号，查到是 student，于是知道是谁"],
  ]}
  columnRatios={[0.5, 0.8, 3.6]}
/>

客户端存起来的这小段数据叫 **Cookie**。服务器那边「编号对应哪个用户」的记录叫**会话**（session）。（来源：[RFC 6265](#source-rfc6265)、[MDN: An overview of HTTP](#source-mdn-http-overview)、[MDN: Using HTTP cookies](#source-mdn-http-cookies)）

浏览器会自动完成第 3、4 步。`curl` 需要你告诉它存在哪、从哪取：

<TerminalSession
  title="终端 B：带着 Cookie 再访问"
  steps={[
    {
      cmd: "curl -s -o /dev/null -c cookies.txt -d 'user=student&password=kali123' http://127.0.0.1:8000/login",
      note: '再登录一次。-c cookies.txt 把服务器发来的 Cookie 存进文件；-s -o /dev/null 不显示别的输出。',
    },
    {
      cmd: 'cat cookies.txt',
      out: '# Netscape HTTP Cookie File\n# https://curl.se/docs/http-cookies.html\n# This file was generated by libcurl! Edit at your own risk.\n\n#HttpOnly_127.0.0.1\tFALSE\t/\tFALSE\t0\tsession\teaf1ba536d7cc01f',
      note: '最后一行的末尾两项就是 Cookie 的名字和值。',
    },
    { cmd: 'curl -b cookies.txt http://127.0.0.1:8000/me', out: 'Welcome back, student.', note: '-b cookies.txt 把文件里的 Cookie 带上。服务器认出来了。' },
    {
      cmd: 'curl -v -b cookies.txt http://127.0.0.1:8000/me',
      out: '*   Trying 127.0.0.1:8000...\n* Established connection to 127.0.0.1 (127.0.0.1 port 8000) from 127.0.0.1 port 54210\n* using HTTP/1.x\n> GET /me HTTP/1.1\n> Host: 127.0.0.1:8000\n> User-Agent: curl/8.21.0\n> Accept: */*\n> Cookie: session=eaf1ba536d7cc01f\n>\n* Request completely sent off\n< HTTP/1.1 200 OK\n< Server: PracticeSite/1.0\n< Date: Thu, 01 Oct 2026 16:45:28 GMT\n< Content-Type: text/plain; charset=utf-8\n< Content-Length: 23\n<\nWelcome back, student.\n* Connection #0 to host 127.0.0.1:8000 left intact',
      note: '这就是引导问题的答案：请求里多了一行 Cookie。服务器认人，靠的只是这一行。',
    },
  ]}
/>

<Callout variant="warning" title="会话编号等于登录状态">
服务器只看编号，不看是谁送来的。任何人只要拿到你的会话编号，带着它去请求，服务器就会把他当成你。所以 `cookies.txt` 和密码一样要保管好，不要提交进 Git，也不要发给别人。
</Callout>

### 4. 请求里的每一项都是客户端自己填的

<TerminalSession
  title="终端 B：自称是别的程序"
  steps={[
    {
      cmd: "curl -v -H 'User-Agent: Mozilla/5.0 (not really)' http://127.0.0.1:8000/hello",
      out: '*   Trying 127.0.0.1:8000...\n* Established connection to 127.0.0.1 (127.0.0.1 port 8000) from 127.0.0.1 port 54212\n* using HTTP/1.x\n> GET /hello HTTP/1.1\n> Host: 127.0.0.1:8000\n> Accept: */*\n> User-Agent: Mozilla/5.0 (not really)\n>\n* Request completely sent off\n< HTTP/1.1 200 OK\n< Server: PracticeSite/1.0\n< Date: Thu, 01 Oct 2026 16:45:28 GMT\n< Content-Type: text/plain; charset=utf-8\n< Content-Length: 17\n<\nHello, stranger!\n* Connection #0 to host 127.0.0.1:8000 left intact',
      note: '-H 可以加上或替换任何一个请求头。User-Agent 变成了你写的内容。',
    },
  ]}
/>

上一课说过，请求只是一段文字。头部也一样，客户端写什么，服务器收到的就是什么。**服务器没有办法知道这些内容是不是真的。** 这句话下学期会反复用到。

边界：这一课用的是 `http://`，请求和响应在网络上是明文，路上的任何设备都能读到密码和 Cookie。真实网站用 `https://`，对话的格式完全相同，只是整段对话在一条加密的连接里进行。练习站只监听 `127.0.0.1`，数据不出本机，所以可以用明文练习。

<KeyTakeaway>
HTTP 的一次对话是一个请求加一个响应，两者都由起始行、头部、空行、正文组成。请求说明要做什么（方法）和对谁做（目标），响应用状态码给出结果。HTTP 无状态，服务器靠 Cookie 里的会话编号认出同一个人：登录时用 Set-Cookie 发下去，之后每个请求用 Cookie 带回来。请求里的每一项都由客户端填写，服务器无从知道真假。
</KeyTakeaway>
