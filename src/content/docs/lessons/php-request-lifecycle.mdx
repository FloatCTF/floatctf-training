## 引导问题：同一个网址，为什么每个人看到的不一样

第 16 课的 `index.html` 是一个写好的文件，谁来请求，服务器都原样发回去。可是你登录一个网站，首页上写着你的名字；换个人登录，写的是他的名字。服务器上不可能为每个人存一份 HTML。

这样的页面是在请求到达的那一刻，由一段程序当场**生成**的。PHP 就是专门干这件事的语言：它把程序直接写在 HTML 里，请求来了才执行，执行的结果就是发给浏览器的页面。

### 2. 标签：哪些是代码，哪些原样输出

PHP 处理一个文件时，从头读到尾：

- `<?php` 和 `?>` 之间的是 **PHP 代码**，执行它。`echo` 把一段内容输出到当前位置。
- 标签外面的一切原样输出，PHP 不看它是什么。
- `<?= 表达式 ?>` 是 `<?php echo 表达式; ?>` 的简写，专门用来在 HTML 里插一个值。

（来源：[PHP tags](#source-php-tags)）

<FlowSimulator client:visible title="一次请求里 PHP 做的事" steps={lifecycle} motionLevel="explanatory" />

关键在最后一步：**浏览器收到的只是 PHP 的输出。** 用 Firefox 打开这个页面再按 `Ctrl` + `U` 查看源代码，看到的和上面 `curl` 拿到的一样，找不到一行 PHP。源码只在服务器的硬盘上。

和第 19 课的 C 相比，PHP 不需要事先编译：每次请求来了，服务器都把文件交给 PHP 解释器从头执行一遍，改完文件保存就生效。

## 二、读取请求里的数据

### 1. $_GET 和 $_SERVER

<CodeFile file="labs/php-request-lifecycle/request.php" note="header() 设置响应头，这里让它返回纯文本，方便在终端里看。" />

<TerminalSession
  title="终端 B：PHP 眼里的请求"
  steps={[
    {
      cmd: "curl 'http://127.0.0.1:8000/request.php?id=7&sort=name'",
      out: 'method: GET\npath:   /request.php?id=7&sort=name\nquery:  array(2) {\n  ["id"]=>\n  string(1) "7"\n  ["sort"]=>\n  string(4) "name"\n}',
      note: '网址里问号后面的参数，PHP 已经拆好放进了 $_GET。var_dump 打印一个值的类型和内容。',
    },
    {
      cmd: "curl -d 'a=1' http://127.0.0.1:8000/request.php",
      out: 'method: POST\npath:   /request.php\nquery:  array(0) {\n}',
      note: '这次是 POST，网址里没有参数，$_GET 是空的。POST 的正文在 $_POST 里，第 29 课细讲。',
    },
  ]}
/>

`$_GET`、`$_POST`、`$_SERVER` 这些以下划线开头的变量是 PHP 预先准备好的，叫**超全局变量**，在脚本的任何地方都能直接用。`$_GET` 是一个数组，用 `$_GET['id']` 取出名为 `id` 的参数。注意：取出来的永远是**字符串**，`"7"` 不是数字 7。（来源：[Superglobals](#source-php-superglobals)、[$_GET](#source-php-get)）

PHP 的变量名前面都有一个 `$`。

### 2. 同一个文件，不同的页面

<CodeFile file="labs/php-request-lifecycle/greet.php" mark="2" />

<TerminalSession
  title="终端 B：引导问题的答案"
  steps={[
    { cmd: "curl 'http://127.0.0.1:8000/greet.php?name=kali'", out: '<!doctype html>\n<html lang="en">\n<head><meta charset="utf-8"><title>Greet</title></head>\n<body>\n<p>Hello, kali!</p>\n<p>Your name has 4 letters.</p>\n</body>\n</html>', note: '文件开头那段 PHP 只算数，没有输出。紧跟在 ?> 后面的那一个换行也被 PHP 吞掉了，所以响应从 <!doctype html> 开始。' },
    { cmd: "curl -s 'http://127.0.0.1:8000/greet.php?name=administrator' | grep letters", out: '<p>Your name has 13 letters.</p>' },
    { cmd: "curl -s http://127.0.0.1:8000/greet.php | grep Hello", out: '<p>Hello, stranger!</p>', note: '没带 name 参数，用上了默认值。' },
  ]}
/>

第 2 行的 `$_GET['name'] ?? 'stranger'` 的意思是：如果有 `name` 这个参数就用它，没有就用 `'stranger'`。**请求里的参数可能有、可能没有，用之前要先想好没有时怎么办。**

第 9 行输出名字时套了一层 `htmlspecialchars`。名字是请求者自己填的，可以是任何字符，包括 `<` 和 `>`。这个函数把它们换成 HTML 实体，让它们在页面上显示为字符，而不是被浏览器当成标签。为什么这件事重要，第 29 课再讲；从现在起，**把请求里的数据放进页面之前，都先过一遍 `htmlspecialchars`。**（来源：[htmlspecialchars](#source-php-htmlspecialchars)）

## 三、出错的时候看哪里

### 1. 语法错误：500，空白页

<CodeFile file="labs/php-request-lifecycle/broken.php" mark="3" note="第 3 行末尾漏了分号。" />

<TerminalSession
  title="终端 B：什么都没有"
  steps={[
    { cmd: 'curl -i http://127.0.0.1:8000/broken.php', out: 'HTTP/1.0 500 Internal Server Error\nHost: 127.0.0.1:8000\nDate: Fri, 02 Oct 2026 13:57:28 GMT\nConnection: close\nX-Powered-By: PHP/8.4.24\nContent-type: text/html; charset=UTF-8', note: '状态码 500，正文是空的。连第 2 行的 before 都没有输出。' },
    { cmd: 'php -l broken.php', out: 'PHP Parse error:  syntax error, unexpected token "echo", expecting "," or ";" in broken.php on line 4\nErrors parsing broken.php', note: '-l 只检查语法，不运行。错误是在第 4 行发现的：读到 echo 时它才意识到上一行没有结束。' },
  ]}
/>

同时，终端 A 的日志里多了这样一行：

```text
[Fri Oct  2 13:57:28 2026] PHP Parse error:  syntax error, unexpected token "echo", expecting "," or ";" in /home/kali/lab/php/broken.php on line 4
```

PHP 执行文件之前会先把整个文件解析一遍，语法不对就一行都不执行。报错写进了服务器的日志，**没有发给客户端**。这是正确的做法：报错里有文件路径，不该让访问者看到。

### 2. 运行时警告：页面照常，日志里有话

<CodeFile file="labs/php-request-lifecycle/notice.php" note="没有判断 name 参数是否存在。" />

<TerminalSession
  title="终端 B：少了参数"
  steps={[
    { cmd: 'curl http://127.0.0.1:8000/notice.php', out: 'Hello, ', note: '页面出来了，只是名字是空的。' },
  ]}
/>

终端 A 的日志里：

```text
[Fri Oct  2 13:57:28 2026] PHP Warning:  Undefined array key "name" in /home/kali/lab/php/notice.php on line 2
```

这类问题不会让页面打不开，所以很容易被忽略。开发时一直开着终端 A，每请求一次就瞄一眼日志。

### 3. 开发时把报错显示在页面上

在终端 A 里按 `Ctrl` + `C` 停掉服务器，换个参数重新启动：

<TerminalSession
  environment="KALI 终端 A"
  title="打开 display_errors"
  steps={[
    { cmd: 'php -d display_errors=1 -S 127.0.0.1:8000', out: '[Fri Oct  2 13:57:50 2026] PHP 8.4.24 Development Server (http://127.0.0.1:8000) started\n…', note: '-d 临时改一项设置。display_errors=1 让报错也输出到页面里。' },
  ]}
/>

<TerminalSession
  title="终端 B：报错出现在响应里了"
  steps={[
    { cmd: 'curl http://127.0.0.1:8000/notice.php', out: '<br />\n<b>Warning</b>:  Undefined array key "name" in <b>/home/kali/lab/php/notice.php</b> on line <b>2</b><br />\nHello,' },
  ]}
/>

<Callout variant="warning" title="只在自己的机器上打开">
页面上的报错暴露了服务器上的文件路径，有时还有更多内部信息。真实的网站必须关闭 `display_errors`，报错只写进日志。下学期你会在别人的网站上看到忘了关的报错，那是一种信息泄露。
</Callout>

练完之后在终端 A 按 `Ctrl` + `C` 停掉服务器。（来源：[Built-in web server](#source-php-webserver)）

<KeyTakeaway>
PHP 文件是夹着代码的页面。请求到达时，服务器把 `.php` 文件交给 PHP 从头执行：标签外的内容原样输出，`<?php ?>` 里的代码被执行，`echo` 的结果留在原处，全部输出就是响应。浏览器只收到输出，看不到 PHP 源码。请求里的参数在 `$_GET` 等超全局变量里，可能不存在，永远是字符串，放进页面前要用 `htmlspecialchars` 转义。出错时去看服务器的日志。
</KeyTakeaway>
