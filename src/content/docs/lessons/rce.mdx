## 引导问题：为什么“多打了一个分号”就能执行新命令？

如果程序执行的是：

```bash
ping -c 1 <用户输入>
```

并且这行字符串交给 shell 解析，那么用户输入中的 `;`、`|`、`$()` 会成为 shell 语法，而不是 `ping` 的普通参数。

CWE-78 描述的是 OS 命令中特殊元素中和不足；OWASP 给出攻击说明与防御清单。（来源：[CWE-78](#source-cwe-78)、[OWASP](#source-owasp-command-injection)）

## 两条主路径

1. **命令注入：** 输入进入 shell/命令行。
2. **代码执行：** 输入进入 `eval`、反序列化、模板引擎或表达式引擎。

最终都能控制进程，但审计搜索词和修复点不同。

## 本地演示

```bash
node examples/command-injection-demo.mjs
```

预期：

```text
脆弱命令串： ping -c 1 127.0.0.1; id
安全参数： {"argv":["ping","-c","1","127.0.0.1; id"], ...}
```

在 argv 形式下，`; id` 只是主机名参数的一部分，不会变成第二条命令。真实环境仍要校验主机格式。

## 真实案例

CVE-2021-44228（Log4Shell）展示日志消息中的查找语法如何通向远程加载；Apache 安全页持续记录修复版本。CVE-2022-22965 展示框架数据绑定问题也可形成 RCE。（来源：[CVE-2021-44228](#source-cve-2021-44228)、[Log4j Security](#source-log4j-security)、[CVE-2022-22965](#source-cve-2022-22965)）

## 分层防御

按 OWASP 命令注入防御思路：优先避免调用 OS 命令；必须调用时使用参数化/argv 风格 API；对参数做允许列表；以最小权限运行。（来源：[OWASP Defense](#source-owasp-command-defense)）

<ScrollReveal client:visible motionLevel="explanatory" label="修复复盘">
  <p>修复后的回归应覆盖：原参数位置、二次封装函数、异步任务与运维接口。RCE 入口经常藏在“临时脚本”和“内部工具页”。</p>

## 常见错误与边界

- **过滤空格却放过 `$()` 与换行。**
- **禁用了 `exec`，仍通过模板或反序列化执行。**
- **容器以 root 运行，放大后果。**
- **依赖长期不升级，框架默认特性变成攻击面。**
