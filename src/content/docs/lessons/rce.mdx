## 引导问题：为什么“多打了一个分号”就能执行新命令？

如果程序执行的是：

```bash
ping -c 1 <用户输入>
```

并且这行字符串交给 shell 解析，那么用户输入中的 `;`、`|`、`$()` 会成为 shell 语法；`ping` 无法把它们作为普通参数接收。

CWE-78 描述的是 OS 命令中特殊元素中和不足；OWASP 给出攻击说明与防御清单。（来源：[CWE-78](#source-cwe-78)、[OWASP](#source-owasp-command-injection)）

## 两条主路径

1. **OS 命令注入：** 输入进入 shell 或命令解释路径，可能增加命令、选项或参数。
2. **语言级代码执行：** 输入进入 `eval`、反序列化、模板引擎或表达式引擎，并在当前运行时权限内影响执行流。

两类问题都越过应用预期的执行边界。OS 命令注入可以直接调用外部程序；语言级执行受运行时、沙箱和可用 API 约束。

## 本地演示

```bash
node examples/command-injection-demo.mjs
```

预期：

```text
脆弱命令串： ping -c 1 127.0.0.1; id
恶意输入： {"accepted":false,"reason":"只允许 IP 字面量"}
选项输入： {"accepted":false,"reason":"只允许 IP 字面量"}
合法输入： {"accepted":true,"file":"/usr/bin/ping", ...}
```

脚本只构造调用参数，不启动进程。无 shell 的 argv 形式会消除 shell 元字符语义；参数仍可能被目标程序解释为选项，因此示例限制为 IP 字面量，并用 `--` 结束选项。`--` 属于 POSIX 工具约定，跨平台封装需要按目标程序文档调整。

## 真实案例

CVE-2021-44228 影响特定 Log4j Core 版本：攻击者控制进入日志的消息或参数后，JNDI Lookup 可能从 LDAP 加载并执行代码；Apache 为 Java 6、7、8 及以上分支分别发布了修复版本。CVE-2022-22965 的公开利用场景要求 JDK 9 及以上、受影响 Spring Framework、`spring-webmvc` 或 `spring-webflux`、传统 WAR 部署和特定 Servlet 容器；常见 Spring Boot 可执行 JAR 不受该公开利用链影响。（来源：[CVE-2021-44228](#source-cve-2021-44228)、[Apache 公告](#source-log4j-security)、[CVE-2022-22965](#source-cve-2022-22965)、[Spring 公告](#source-spring-cve-2022-22965)）

## 分层防御

按 OWASP 命令注入防御思路：优先使用语言库替代 OS 命令；必须调用时固定程序、禁用 shell、使用 argv、校验每个参数的语义，并设置最小权限、超时和输出上限。参数数组仍需防止选项注入。（来源：[OWASP Defense](#source-owasp-command-defense)、[Node.js](#source-node-child-process)）

## 常见错误与边界

- **过滤空格却放过 `$()` 与换行。**
- **禁用了 `exec`，仍通过模板或反序列化执行。**
- **容器以 root 运行，放大后果。**
- **依赖长期不升级，框架默认特性变成攻击面。**
