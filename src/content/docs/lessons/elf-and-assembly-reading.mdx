## 引导问题：编译完的二进制是一堆乱码，逆向分析的人到底在看什么

第 19 课你已经知道 `gcc` 把 `.c` 源码翻译成了机器码，可打开编译产物只能看到乱码。拿到一个别人发来的校验程序 `check_pin`，没有源码，怎么知道它究竟在比较什么数字？

答案不在猜，而在按固定顺序把 ELF 文件的结构和对应函数的机器指令反译出来读。先看清一个可执行文件从磁盘到 CPU 执行的五步过程：

下载本课的 28 行示例源码到 `~/lab/elf`（假装一会你只拿到了编译出来的 `check_pin`，用源码和反汇编对照着学最容易建立直觉）：

<CodeFile file="labs/elf-and-assembly-reading/check_pin.c" mark="4-6,8-14" note="compute_code 与 check_pin 两个小函数正好用来观察参数传递、算术运算和条件跳转。" />

## 三、用 `objdump` 逐行读懂一段真实反汇编

加上 `-M intel` 让 `objdump` 按更符合直觉的 Intel 语法输出（来源：[objdump 文档](#source-binutils-objdump)）：

<TerminalSession
  environment="KALI 终端"
  title="反汇编 compute_code 与 check_pin，手工算出正确 PIN"
  steps={[
    {
      cmd: 'objdump -d -M intel --disassemble=compute_code check_pin',
      out: '…\nDisassembly of section .text:\n\n0000000000001149 <compute_code>:\n    1149:\t55                   \tpush   rbp\n    114a:\t48 89 e5             \tmov    rbp,rsp\n    114d:\t89 7d fc             \tmov    DWORD PTR [rbp-0x4],edi\n    1150:\t89 75 f8             \tmov    DWORD PTR [rbp-0x8],esi\n    1153:\t8b 55 fc             \tmov    edx,DWORD PTR [rbp-0x4]\n    1156:\t89 d0                \tmov    eax,edx\n    1158:\t01 c0                \tadd    eax,eax\n    115a:\t01 c2                \tadd    edx,eax\n    115c:\t8b 45 f8             \tmov    eax,DWORD PTR [rbp-0x8]\n    115f:\t01 d0                \tadd    eax,edx\n    1161:\t5d                   \tpop    rbp\n    1162:\tc3                   \tret\n…',
      note: '首尾省略号对应 GNU objdump 自带的文件格式头与 .init/.plt/.plt.got/.fini 空节标题。114d–1150 把第 1 参数 edi 和第 2 参数 esi 存进栈槽；1156–115a 把 a 复制一份相加得 2a，再加回 edx 得 3a；115c–115f 加上 b 放进返回值 eax（不同 gcc 版本指令选择可能略有差异）。',
    },
    {
      cmd: 'objdump -d -M intel --disassemble=check_pin check_pin',
      out: '…\nDisassembly of section .text:\n\n0000000000001163 <check_pin>:\n    1163:\t55                   \tpush   rbp\n    1164:\t48 89 e5             \tmov    rbp,rsp\n    1167:\t48 83 ec 18          \tsub    rsp,0x18\n    116b:\t89 7d ec             \tmov    DWORD PTR [rbp-0x14],edi\n    116e:\tbe e2 00 00 00       \tmov    esi,0xe2\n    1173:\tbf 78 05 00 00       \tmov    edi,0x578\n    1178:\te8 cc ff ff ff       \tcall   1149 <compute_code>\n    117d:\t89 45 fc             \tmov    DWORD PTR [rbp-0x4],eax\n    1180:\t8b 45 ec             \tmov    eax,DWORD PTR [rbp-0x14]\n    1183:\t3b 45 fc             \tcmp    eax,DWORD PTR [rbp-0x4]\n    1186:\t75 07                \tjne    118f <check_pin+0x2c>\n    1188:\tb8 01 00 00 00       \tmov    eax,0x1\n    118d:\teb 05                \tjmp    1194 <check_pin+0x31>\n    118f:\tb8 00 00 00 00       \tmov    eax,0x0\n    1194:\tc9                   \tleave\n    1195:\tc3                   \tret\n…',

<Callout type="note" title="什么时候停在 objdump，什么时候上反编译器">
对几十行的小函数，直接看 `objdump -d -M intel` 最干净、零误差；遇到几万行的大型二进制或去符号（stripped）程序时，安全研究员会用 Ghidra、IDA 或 Binary Ninja 把汇编还原成类 C 伪代码——但伪代码偶尔会推断失真，能看懂这节课的基础汇编就是你复核反编译结果的底气。
</Callout>

<KeyTakeaway>
二进制不是黑魔法：file 定身份，readelf 看分区，strings 找线索，objdump -d -M intel 对着 rdi/rsi/rax 与 cmp/jne 读逻辑。哪怕你主攻 Web 安全，掌握这套最小静态读图能力，也能在跨方向题目和底层排错里从容上手。下一课我们把视野拉回全局，讲清安全思维、法律红线与 AI 时代的高效读码工作流。
</KeyTakeaway>
