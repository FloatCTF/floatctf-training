## 引导问题：这串字符是什么

入门的 CTF 题目里经常出现这样的字符串：

```text
NjY2YzYxNjc3YjY4NjU2YzZjNmY3ZA==
```

它看起来像乱码，实际上是一句普通的话被换了两次写法。这一课结束时，你会用一条命令把它还原，并且知道每一步发生了什么。

线索有两个：结尾的 `==`，以及只出现大小写字母和数字。先记住这两个特征，第三节回来解它。

## 一、位、字节与三种进制

### 1. 位和字节

计算机里最小的存储单位是**位**（bit），只有 0 和 1 两种状态。8 个位组成一个**字节**（byte）。（来源：[CS50x Week 0](#source-cs50-week0)）

8 个位一共有 2⁸ = 256 种组合，所以一个字节能表示 0 到 255 之间的一个数。文件大小、网络流量、内存容量，数的都是字节。上节课 `ls -l` 显示 `first.txt` 的大小是 11，意思就是这个文件由 11 个字节组成。

### 2. 同一个数的三种写法

人习惯用十进制，计算机内部是二进制，而二进制写出来太长。于是有了**十六进制**：用 0 到 9 和 a 到 f 共 16 个符号，每个符号正好对应 4 个位。（来源：[RFC 4648](#source-rfc4648)）

一个字节是 8 个位，写成十六进制正好是两个符号。这就是十六进制到处出现的原因。

<DataTable
  caption="同一个字节的三种写法"

  rows={[
    ["0", "00000000", "00", "0×16 + 0"],

十六进制和二进制之间不用算，直接查：每个十六进制符号展开成 4 个位。`4b` 的 `4` 是 `0100`，`b` 是 `1011`，拼起来就是 `01001011`。

为了和十进制区分，十六进制数前面常加 `0x`，例如 `0x41`。

## 二、文字怎样变成字节

### 1. ASCII：给每个字符一个编号

字节只能存数。要存文字，就得约定「哪个数代表哪个字符」。最早被广泛使用的约定是 **ASCII**：它给英文字母、数字、标点和一些控制符号各分配了一个 0 到 127 之间的编号。大写 A 是 65，小写 a 是 97。（来源：[RFC 20](#source-rfc20)）

`xxd` 能把数据的每个字节打印出来：

<TerminalSession
  title="用 xxd 看字节"
  steps={[

    { cmd: "printf 'A' | xxd -b", out: '00000000: 01000001                                               A', note: '-b 把每个字节显示成 8 个二进制位。' },
    { cmd: "printf 'Hi\\n' | xxd", out: '00000000: 4869 0a                                  Hi.', note: '\\n 是换行符，它也是一个字节，值是 0x0a。' },
    { cmd: 'xxd notes/first.txt', out: '00000000: 6865 6c6c 6f20 6b61 6c69 0a              hello kali.', note: '10 个可见字符加 1 个换行，一共 11 个字节，和 ls -l 显示的大小一致。' },
  ]}
/>

### 2. UTF-8：让一个字符占多个字节

ASCII 只有 128 个编号，放不下中文。**Unicode** 给世界上的每个字符分配了一个编号，叫码点，写作 `U+` 加十六进制，例如「中」是 U+4E2D。**UTF-8** 规定了怎样把码点存成字节：编号小的字符用 1 个字节，大的用 2 到 4 个。

<DataTable
  caption="UTF-8 用几个字节"
  headers={["码点范围", "字节数", "例子"]}
  rows={[
    ["U+0000 到 U+007F", "1", "英文字母、数字、常用标点。和 ASCII 完全相同"],
    ["U+0080 到 U+07FF", "2", "带重音的拉丁字母、希腊字母等"],
    ["U+0800 到 U+FFFF", "3", "绝大多数汉字"],
    ["U+10000 到 U+10FFFF", "4", "表情符号、生僻字"],
  ]}
  columnRatios={[1.4, 0.7, 2.6]}
/>

（来源：[RFC 3629](#source-rfc3629)）

<TerminalSession
  title="一个汉字，三个字节"
  steps={[
    { cmd: "printf '中' | xxd", out: '00000000: e4b8 ad                                  ...', note: '三个字节：e4 b8 ad。右栏显示成三个点，因为 xxd 按单个字节显示，认不出多字节的字符。' },
    { cmd: "printf '中' | wc -c", out: '3', note: 'wc -c 数字节。' },

字符数和字节数是两回事。程序里凡是涉及「长度」的地方，都要先问清楚数的是哪一个。

## 三、Base64 与 URL 编码

### 1. 十六进制字符串

把每个字节写成两个十六进制字符、连在一起，就得到十六进制字符串。它只含 0 到 9 和 a 到 f，可以放心地复制粘贴。代价是长度翻倍。

<TerminalSession
  title="字节与十六进制字符串互转"
  steps={[
    { cmd: "printf 'hello' | xxd -p", out: '68656c6c6f', note: '-p 只输出连续的十六进制，不带偏移和文本栏。' },
    { cmd: 'echo 68656c6c6f | xxd -r -p', out: 'hello', note: '-r 反向转换：把十六进制还原成字节。' },
  ]}
/>

### 2. Base64：每 3 个字节写成 4 个字符

很多场合只能传输文字，例如邮件正文、网页里的一段文本。要在这些地方传递任意字节，就需要把字节换成一组安全的字符。**Base64** 用 64 个字符：大小写字母 52 个、数字 10 个，加上 `+` 和 `/`。

64 = 2⁶，每个字符正好表示 6 个位。规则是：把输入每 3 个字节（24 位）分成一组，切成 4 个 6 位，每个 6 位查表换成一个字符。最后一组不足 3 个字节时，用 `=` 补齐到 4 个字符。（来源：[RFC 4648](#source-rfc4648)）

<TerminalSession
  title="补位的三种情况"
  steps={[
    { cmd: "printf 'Man' | base64", out: 'TWFu', note: '正好 3 个字节，4 个字符，不需要补位。' },
    { cmd: "printf 'Ma' | base64", out: 'TWE=', note: '剩 2 个字节：3 个字符加一个 =。' },
    { cmd: "printf 'M' | base64", out: 'TQ==', note: '剩 1 个字节：2 个字符加两个 =。' },
    { cmd: "echo 'aGVsbG8=' | base64 -d", out: 'hello', note: '-d 是解码。' },
  ]}
/>

所以结尾的一两个 `=` 是 Base64 最明显的特征。长度方面，3 个字节变 4 个字符，大约膨胀到原来的三分之四。

### 3. URL 编码：%XX

URL 里有些字符有特殊含义，例如 `&` 分隔参数、`=` 连接名和值、空格则根本不允许出现。要把这些字符当作普通数据放进 URL，就把对应的字节写成 `%` 加两位十六进制。中文先按 UTF-8 变成字节，再逐个字节这样写。（来源：[RFC 3986](#source-rfc3986)）

终端里没有专门的命令，这里借用 Python 的一行写法，先照抄，Python 从下一课开始学：

<TerminalSession
  title="URL 编码与解码"
  steps={[
    { cmd: "python3 -c \"import urllib.parse; print(urllib.parse.quote('a b&c=中'))\"", out: 'a%20b%26c%3D%E4%B8%AD', note: '空格是 %20，& 是 %26，= 是 %3D。「中」的三个字节 e4 b8 ad 变成 %E4%B8%AD。' },
    { cmd: "python3 -c \"import urllib.parse; print(urllib.parse.unquote('flag%7Burl%7D'))\"", out: 'flag{url}', note: '%7B 和 %7D 是一对花括号。' },
  ]}
/>

### 4. 编码不是加密

<Callout variant="warning" title="看不懂不等于安全">
十六进制、Base64、URL 编码都是**编码**：规则公开，不需要密钥，任何人都能还原。它们的作用是让数据能在某种场合安全地传输和显示。**加密**需要密钥，没有密钥的人还原不了。把密码做一次 Base64 存起来，等于明文存放。
</Callout>

<KeyTakeaway>
一切数据都是字节。十六进制是字节最直接的写法，两个字符一个字节；UTF-8 决定文字变成哪些字节；Base64 把每 3 个字节写成 4 个字符，结尾用 = 补齐。这些都是编码，规则公开、可以无损还原，不提供任何保密性。
</KeyTakeaway>
