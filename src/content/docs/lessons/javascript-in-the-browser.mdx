## 引导问题：页面没有刷新，内容怎么变了

你在一个网页上点「加载更多」，新的内容就出现在下面，地址栏没变，页面也没有重新加载。

按前几课的知识，这有两点说不通：内容是从服务器来的，那就得发请求，可是你没有打开新网址；页面是照着 DOM 画的，那就得有人去改 DOM，可是你没有打开控制台。

替你做这两件事的，是页面里的一段 **JavaScript**。它和 HTML 一起从服务器下载下来，在你的浏览器里运行。（来源：[MDN: What is JavaScript?](#source-mdn-js-what)）

## 二、让页面对点击作出反应

### 1. 脚本是怎样进到页面里的

`index.html` 的倒数第三行：

```html
<script src="app.js"></script>
```

浏览器解析到这一行，就去请求 `app.js`，拿到之后立刻从上到下运行一遍。终端 A 的日志里能看到这个请求：

```text
127.0.0.1 - - [01/Oct/2026 17:06:37] "GET / HTTP/1.1" 200 -
127.0.0.1 - - [01/Oct/2026 17:06:37] "GET /app.js HTTP/1.1" 200 -
```

这一行放在 `body` 的最后，是有原因的：脚本运行时，它前面的元素已经解析好了，脚本才找得到它们。（来源：[MDN: script](#source-mdn-script)、[MDN: What is JavaScript?](#source-mdn-js-what)）

服务器只是把 `app.js` 当作一个普通文件发出去。**运行它的是你的浏览器。**

### 2. 事件：等某件事发生再运行

看 `app.js` 的前八行：

```js
let count = 0;

function handleClick() {
  count = count + 1;
  document.querySelector("#count").textContent = count;
}

document.querySelector("#add").addEventListener("click", handleClick);
```

```js
async function loadItems() {
  const response = await fetch("/api/items?page=1");
  const data = await response.json();
  for (const item of data.items) {
    const li = document.createElement("li");
    li.textContent = item.name + " - " + item.price;
    document.querySelector("#items").appendChild(li);
  }
}

document.querySelector("#load").addEventListener("click", loadItems);
```

去看终端 C 的日志：


### 4. 为什么要有这条规矩

第 14 课讲过，浏览器访问一个站点时会自动带上那个站点的 Cookie。假设你登录了邮箱，又打开了另一个不怀好意的网页。那个网页里的脚本可以让你的浏览器向邮箱发请求，请求会带着你的 Cookie，邮箱服务器会把它当成你。

如果没有同源策略，那段脚本就能读到响应，也就是你的邮件。有了它，响应回到浏览器之后不会交给别的源的脚本。（来源：[MDN: Same-origin policy](#source-mdn-same-origin)）

<KeyTakeaway>
JavaScript 随页面一起下载，在你的浏览器里运行。它用 `addEventListener` 等待点击这类事件，在函数里读写 DOM，用 `fetch` 向服务器要数据，于是页面不刷新也能变化。脚本和它的变量对使用者完全透明，不能用来保护任何东西。浏览器给脚本划了一条线：默认只能读取同源（协议、主机、端口都相同）的响应；跨源的请求照样会发出去，只是响应不交给脚本。
</KeyTakeaway>
