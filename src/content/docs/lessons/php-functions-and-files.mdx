## 引导问题：改一处导航，要改几个文件

假设你的网站有十个页面，每个页面顶上都有一行导航。现在要在导航里加一个链接。

如果导航是复制粘贴到十个文件里的，就得改十次，而且总有一次会漏掉。第 25 课的 C 用头文件解决了同样的问题：公共的东西只写一份，谁要用就包含进来。PHP 也有这样的机制，而且它包含的不只是函数，还可以是一段 HTML。

第 28 课讲过，PHP 会自动转换类型，`"5" + 3` 得 8。**类型声明**关掉了函数入口处的这种自由：参数必须是声明的类型，否则直接报错，而不是悄悄转换后算出一个莫名其妙的结果。自己写函数时，给参数和返回值都写上类型。（来源：[Type declarations](#source-php-declarations)、[Functions](#source-php-functions)）

### 2. require 和 __DIR__

`use_lib.php` 第 2 行的 `require __DIR__ . '/lib.php';` 把 `lib.php` 的内容包含进来执行，之后就能调用里面定义的函数。

`__DIR__` 是当前这个文件所在的目录。为什么不直接写 `require 'lib.php'`？因为相对路径是相对于「从哪里运行」来解释的，换个目录运行就可能找不到。`__DIR__` 永远指向这个文件自己所在的位置，拼出来的路径不会错。（来源：[Magic constants](#source-php-magic-constants)）

### 2. 读哪个文件，由谁决定

<CodeFile file="labs/php-functions-and-files/page.php" mark="2-5,9,14" />

<TerminalSession
  title="终端 B：在名单里，和不在名单里"
  steps={[
    { cmd: "curl 'http://127.0.0.1:8000/page.php?name=rules'", out: 'Be kind. No spam.' },
    {
      cmd: "curl -i 'http://127.0.0.1:8000/page.php?name=secret'",
      out: 'HTTP/1.1 404 Not Found\nHost: 127.0.0.1:8000\nDate: Fri, 02 Oct 2026 14:09:53 GMT\nConnection: close\nX-Powered-By: PHP/8.4.24\nContent-Type: text/plain; charset=utf-8\n\nNo such page.',
    },
  ]}
/>

`page.php` 让访问者用 `name` 参数选择要看的说明页。关键在于：**请求里的值只用来在名单里查找，拼进文件路径的永远是名单里写死的文件名。** 不在名单里，一律 404。

<Callout variant="warning" title="不要把请求里的值直接拼成路径">
`file_get_contents(__DIR__ . '/' . $_GET['name'])` 这样的写法，等于让访问者自己决定服务器读哪个文件。你无法预料对方会填什么，程序也就无法保证只读到你想给人看的那几个文件。`include`、`require` 也是一样，而且后果更严重：被包含的文件会被当作 PHP 代码执行。读写和包含文件时，路径只能由程序决定。
</Callout>

练完之后在终端 A 按 `Ctrl` + `C` 停掉服务器。

<KeyTakeaway>
函数参数和返回值写上类型，类型不符时 PHP 直接报错而不是悄悄转换。公共的函数和页面片段各放一个文件，用 `require __DIR__ . '/文件'` 包含进来；必需的文件用 `require`，找不到就停下。`file_put_contents` 和 `file` 读写服务器上的文件，存的时候原样存，输出到 HTML 时再转义。读哪个文件、包含哪个文件，只能由程序按名单决定，不能直接用请求里的值拼路径。
</KeyTakeaway>
