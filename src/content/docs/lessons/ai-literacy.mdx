## 引导问题：模型怎样选出下一个 token

给定一句未完成的话：

```text
漏洞修复后，下一步应该运行___
```

模型会为整个词表计算分数。上下文让“测试”“构建”“扫描”等 token 获得不同概率。生成过程选择一个 token，把它追加到上下文，再计算下一轮概率。自回归语言模型以这个循环逐步生成序列。（来源：[Language Models are Few-Shot Learners](#source-brown-2020)）

一轮生成可以写成：

```text
文本 → token ID → 向量 → Transformer → logits → softmax → 概率 → 选取 token
```

这条数据流把三类影响分开：Tokenizer 决定输入怎样编码，Transformer 决定上下文怎样组合，采样策略决定怎样从概率分布中选取 token。

回答也不是一次性算出来的。模型每轮只预测下一个 token，选出的 token 拼回输入再进入下一轮，这个循环叫**自回归生成**：

<AutoregressiveLoop />

对话界面逐步显示输出，对应的是生成 token 的循环：每生成一个新 token，模型执行一次增量前向计算；常见实现用 KV cache 复用此前 token 的注意力键和值，避免每轮重算全部历史位置。

## 一、文本怎样进入模型

### 1. Tokenizer 把文本变成整数序列

**Token** 是模型词表中的一个离散单位，可以是字、词的一部分、标点或特殊符号。**Tokenizer** 负责文本与 token ID 之间的双向转换。（来源：[Hugging Face LLM Course](#source-hf-llm-course)）

```text
输入文本：修复 SQL 注入
示意切分：["修复", " SQL", " 注入"]
token ID：[1842, 7650, 912]
```

不同 tokenizer 会产生不同切分。token 数影响三件事：

- 文本占用多少上下文空间。
- 输出需要多少个生成步骤。
- 生僻术语、代码和多语言文本的编码效率。

<Callout variant="note" title="切分边界">
Token 与自然语言中的“词”没有一一对应关系。统计分词会依据训练语料和词表规则拆分字符串；同一个中文词、变量名或 URL 可能占用多个 token。
</Callout>

### 2. Embedding 把 ID 映射成向量

整数 ID 只是编号，就像学号：看到学号本身，你对这个人的高矮性格一无所知。**Embedding** 给每个编号配一组数字（向量），这组数字就是模型眼里该 token 的画像，由一张可训练的向量表按 ID 查出。训练会调整这些向量，让后续网络能够利用 token 之间的语义和语法关系。训练后的向量空间通常呈现一条几何性质：语义相近的 token，向量距离也更近。这条性质后来被推广到整段文本的嵌入，是《AI 工程全景》一课中向量检索与 RAG 的基础。

```text
token ID 912 → [0.21, -0.04, 0.73, ...]
```

<EmbeddingSpace />

模型还会注入位置信息，让注意力区分 token 的先后与距离。原始 Transformer 将正弦与余弦位置编码加到输入向量上；后续模型也采用其他位置表示方案。（来源：[Attention Is All You Need](#source-vaswani-2017)）

### 3. Logit 与 softmax 形成概率分布

模型最后一层为词表中的每个 token 输出一个 **logit**。Logit 是未归一化分数。Softmax 把一组 logits 转为总和等于 1 的概率：

```text
p_i = exp(z_i) / Σ_j exp(z_j)
```

下面的数值用于展示上下文怎样改变候选分布，不代表具体模型的实测结果：

### 4. 交叉熵把错误变成训练信号

假设正确 token 是“测试”，模型给出的概率为 `p=0.58`。单步交叉熵损失为：

```text
loss = -ln(p) = -ln(0.58) ≈ 0.545
```

正确 token 的概率越高，损失越低。训练会汇总批次中多个位置的损失，再通过反向传播调整参数。**困惑度**常写为平均交叉熵的指数：

```text
perplexity = exp(average loss)
```

单 token 时这两步可以现场验算——损失是 −ln(p)，再取指数恰好回到 1/p：

## 二、自注意力怎样组合上下文

### 1. 每个位置怎样读取其他位置

理解注意力最快的方式是借图书馆检索：你带着一个问题去书架找书。**Query** 是你的问题（我在找什么），**Key** 是每本书书脊上的标签（这本书讲什么），问题与标签匹配得越好，这本书的权重越高；**Value** 是书的内容，最终你带走的是按权重混合后的内容。注意力把这个过程做成数学：每个位置用 Query 去和所有位置的 Key 打分，按分数加权求和 Value。

工程上，每个位置的向量通过三组可训练矩阵得到这三个角色：

```text
Q = XW_Q    K = XW_K    V = XW_V
Attention(Q,K,V) = softmax(QKᵀ / √d_k)V
```

计算分成三步：

1. `QKᵀ` 计算一个位置与其他位置的匹配分数。
2. 除以 `√d_k` 控制内积随维度增长造成的数值幅度。
3. Softmax 得到权重，再对 `V` 加权求和。

以“它”指代哪个对象为例：

```text
服务器读取配置文件，因为它需要加载端口设置。
```

“它”的 Query 会与“服务器”“配置文件”等位置的 Key 计算匹配分数。模型根据权重组合相应 Value，形成当前层的新表示。把整句话所有位置两两配对，就得到下面这张注意力矩阵——行是发问的 Query，列是被看的 Key，右上三角被因果遮罩屏蔽（下一小节展开）。换一个头，同一句话会得到完全不同的权重图：

<AttentionExplorer client:visible motionLevel="explanatory" />

<IntuitionBox>
Query 表示当前位置用于发起匹配的表示，Key 表示每个位置用于接受匹配的表示，Value 提供加权组合的内容。三者都由可训练矩阵投影得到。
</IntuitionBox>

### 2. 因果遮罩限制信息方向

生成式语言模型需要预测后续 token。**因果遮罩**屏蔽未来位置，使第 `t` 个位置只能利用 `1...t` 的信息：模型写第 4 个词时可以看前 3 个词，不能偷看第 5 个词。训练时可以并行计算各位置的下一 token 损失，同时保持信息只能由前向后流动。

### 3. 多头、残差和前馈网络各自承担什么

**多头注意力**让不同头在不同投影空间中组合信息。一个头可能关注局部语法，另一个头可能关联远距离标识符；具体模式由训练形成，单个头的含义通常缺少稳定的人类标签。

原始 Transformer 将这些组件堆叠成编码器和解码器。常见生成式大模型多采用带因果遮罩的解码器堆叠。Q、K、V 公式描述了核心注意力计算，具体模型会调整位置编码、归一化顺序、激活函数和注意力实现。（来源：[Attention Is All You Need](#source-vaswani-2017)）

## 三、模型怎样训练、对齐和生成

### 1. 预训练闭环

预训练的规模值得先建立一个直觉：GPT-3 的训练数据约 3,000 亿 token（来源：[Language Models are Few-Shot Learners](#source-brown-2020)）。为了统一单位，下面假设每天机械处理 1 万 token，只做数量级换算：

<TrainingScale />

模型在这样的语料上反复做「预测下一个 token」这一件事，语言规律、常识片段和世界知识就沉淀进了参数。

上一节的“前向计算、损失、反向传播、参数更新”在这里保持成立。语言模型把预测目标具体化为下一 token，并把输入具体化为 token ID 序列。

<StepList title="一次训练迭代的数据流" steps={trainingSteps} />

训练集损失持续下降只说明模型更贴合训练数据。完整评估还要检查：

- 验证集损失是否同步下降。
- 不同主题、语言和长度上的误差是否集中。
- 生成结果是否复现训练文本或暴露敏感内容。
- 数据、代码、随机种子和依赖版本能否复现。

### 2. 参数更新与上下文控制作用在不同阶段

从预训练到能对话的模型，中间还要两步加工，可以类比学写作文的过程：预训练像海量阅读，攒下语感和素材；监督微调像照着范文练格式，学会「问什么、怎么答」；偏好对齐像老师把两篇作文摆在一起说「这篇更好」，模型据此调整风格与边界。

### 3. Temperature 和 top-p 改变采样

模型每步给出一组概率，但落笔写哪个 token 还要看采样策略。**Temperature** 调整概率的集中程度：

```text
p_i = softmax(z_i / T)
```

亲手拖一拖比看三张静态图更直接——同一组候选分数，温度从 0.1 拉到 3.0，分布从「几乎锁定」变成「近乎均匀」；再收窄 top-p，看长尾 token 怎样被砍出场：

<SamplingPlayground client:visible motionLevel="explanatory" />

- 较低 `T` 让高分 token 更集中，输出通常更稳定。
- 较高 `T` 让分布更平，输出差异通常增大。
- `top-p` 从累计概率达到阈值的最小候选集合中采样，先砍掉长尾再抽。

采样参数只改变从现有概率分布中选取 token 的方式。事实与逻辑仍需外部证据、测试或人工审查验证。

## 四、上下文窗口的成本与边界

### 1. 全注意力包含 n×n 个位置关系

序列长度为 `n` 时，每个位置都要和其他所有位置两两配对，稠密全注意力的核心计算量随 `n²` 增长：长度翻倍，计算量翻四倍；长度变十六倍，计算量翻二百五十六倍。朴素实现还会显式保存同规模的分数或权重矩阵；优化内核可以减少这些中间结果的显存占用。（来源：[Attention Is All You Need](#source-vaswani-2017)）

这张表只计算位置关系的数量。真实显存还受到数据类型、头数、层数、批量大小、KV cache、反向传播和内核实现影响。FlashAttention 使用分块计算减少 GPU 内存读写，保持精确注意力结果；稠密全注意力的核心计算量仍随序列长度平方增长。（来源：[FlashAttention](#source-dao-2022-flashattention)）

### 2. 信息进入窗口后仍要经过利用

“Lost in the Middle”通过多文档问答和键值检索控制相关信息的位置。实验发现，部分模型在相关信息位于开头或结尾时表现较高，信息位于长上下文中部时表现下降。（来源：[Lost in the Middle](#source-liu-2023)）

工程上可以从四个位置改善信息利用：

1. 检索与当前问题直接相关的片段。
2. 按相关性排序，把关键证据放在更靠前的位置。
3. 删除重复、过期和弱相关内容。
4. 对关键约束建立独立测试，避免只依赖模型记忆。

长上下文表现取决于具体模型、任务和提示结构。“中部信息更难利用”来自受控实验，适用范围需要在目标模型和任务上重新评估。

## 常见错误与能力边界

- **Token 与自然语言词：** 代码、中文和 URL 的切分经常跨越自然语言词界。
- **概率与事实：** 最高概率表示模型在当前输入下的预测，事实需要外部证据验证。
- **训练损失与综合能力：** 验证集、任务评测、安全性和数据泄漏需要分别检查。
- **窗口容量与信息利用：** 信息位置、噪声和检索方式都会影响长上下文表现。
- **单次输出与稳定评测：** 采样具有随机性，可靠评测需要固定数据、参数并重复运行。
