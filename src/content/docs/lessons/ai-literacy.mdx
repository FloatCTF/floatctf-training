## 引导问题：模型到底是怎么「吐出」下一个字的

先看一句没写完的话：

```text
漏洞修复后，下一步应该运行___
```

你脑子里会立刻蹦出「测试」「扫描」「构建」，大概率不会蹦出「删除」。大语言模型也是这样工作的：它把整张词表里的每个候选都打一遍分，算成概率，抽中一个拼到句子尾巴上，再把变长的句子重新喂给自己，接着猜下一个（来源：[Language Models are Few-Shot Learners](#source-brown-2020)）。

这条流水线只有一排，却决定了后面所有问题的排查入口：

```text
文字 → token ID → 向量 → Transformer（自注意力）→ logits → softmax 概率 → 采样选词
```

聊天框里字一个一个往外蹦，不是前端故意加的打字机特效，而是模型真的在**一轮接一轮地做自回归接龙**：

<AutoregressiveLoop />

为了不在每吐一个字时把前面几千个字全重算一遍，推理引擎会用 **KV Cache** 把已经算好的历史键（Key）和值（Value）存进显存，每轮只增量算最新那个词。

## 一、文字是怎么变成模型能算的数字的

### 1. Tokenizer：把字符串切成整数编号

模型不认识汉字，也不认识英文字母，它只认识整数。**Tokenizer（分词器）**负责把文本切成词表里的最小单位 **Token**，再编成整数 ID（来源：[Hugging Face LLM Course](#source-hf-llm-course)）：

```text
原文：    修复 SQL 注入
示意切分：["修复", " SQL", " 注入"]
Token ID：[1842, 7650, 912]
```

Token 数量直接决定三笔账：**占多少上下文窗口、输出要循环跑多少步（耗时和费用）、生僻词和代码要被拆成多少碎片**。

<Callout variant="note" title="Token 不等于日常说的「一个词」">
分词器按训练语料的统计频率切分字符串。常见英文单词可能只占 1 个 token，而一个生僻汉字、长变量名或 URL 往往会被拆成好几个 token，所以同一段话在不同模型里的 token 数并不一样。
</Callout>

### 2. Embedding：从编号变成有意义的坐标

Token ID 只是学号——光看「912」和「913」两个编号，你猜不出这两个词意思近不近。**Embedding（词嵌入）**就是查一张可训练的大表，把每个编号映射成一串高维小数向量（比如 4096 维）：

```text
token ID 912 → [0.21, -0.04, 0.73, ...]
```

经过大量文本训练后，这张向量空间会自动长出漂亮的几何规律：**意思相近、用法相似的词会聚在相邻区域**，无关的词拉得很远。这套「把意思变成空间距离」的本事，后来扩展到整段文档，成了第五课向量检索与 RAG 的地基。

<EmbeddingSpace />

因为 Transformer 并行看所有词、本身不分先后，模型还会在向量里注入**位置编码**，告诉注意力每个词排第几、相隔多远（来源：[Attention Is All You Need](#source-vaswani-2017)）。

### 3. Logit、Softmax 与交叉熵：猜错怎么扣分

经过几十层 Transformer 计算后，输出层给词表里几万个候选词每人发一个原始分数 **logit**，再过一层 **softmax** 变成加起来等于 1 的概率分布。上下文只要换两个词，整组候选的概率就会大洗牌：

训练时怎么打分？直接拿真实文本里的下一个词（比如「测试」）套交叉熵：`loss = -ln(p)`。模型给「测试」的概率是 `0.58`，这一步损失就是 `-ln(0.58) ≈ 0.545`。

论文里常用来比模型好坏的**困惑度（Perplexity）**，其实就是平均交叉熵取个指数：`exp(average loss)`。单步时它刚好等于 `1 / p`，表示模型给真实 token 分配的概率有多低（等价于在多少个等概率候选里盲选）：

## 二、自注意力：一句话里谁该参考谁

### 1. 用图书馆找书理解 Q、K、V

读「服务器读取配置文件，因为**它**需要加载端口设置」这句话时，看到「它」，你会自动回头确认它指代「服务器」而不是「配置文件」。自注意力干的就是这件事，最快记法是图书馆找书：

- **Query（查询）**：当前这个词手里的问题——「我需要找谁来帮我理解自己？」
- **Key（键）**：句子里每个词书脊上的标签——「我能提供什么信息？」
- **Value（值）**：书里真正的内容。

模型把每个词的向量分别乘三个可训练矩阵，投影出 Q、K、V，再按三步算完（来源：[Attention Is All You Need](#source-vaswani-2017)）：

```text
Q = XW_Q    K = XW_K    V = XW_V
Attention(Q, K, V) = softmax(QKᵀ / √d_k) V
```

1. `QKᵀ` 算当前词和句子里每个词的匹配度；
2. 除以 `√d_k` 防止向量维度太大时内积爆掉、把 softmax 挤成极端；
3. Softmax 变成加起来为 1 的权重，按权重把大家的 `V` 混在一起。

### 2. 因果遮罩：写第 4 个词时绝不能偷看第 5 个词

训练时整句话是一起送进显卡并行算的。如果不拦一下，第 3 个词就会直接抄第 4 个词的答案，那还学什么预测？

**因果遮罩（Causal Mask）**把矩阵右上三角（未来位置）的打分直接填成负无穷，经过 softmax 权重变成严格的 `0`。这样既能整句并行训练，又能守住「只能看前文、不能偷看未来」的铁律：

把注意力层叠成大模型，每一层（Block）通常由四个零件协作完成（来源：[Attention Is All You Need](#source-vaswani-2017)）：

主流生成式大模型（GPT、Claude、DeepSeek 等）大多采用带因果遮罩的解码器堆叠结构，各家差异主要在位置编码方式（如 RoPE）、归一化顺序、激活函数以及注意力显存优化上。

## 三、从预训练到对齐，再到落笔采样

像 Stanford CS336 这类现代大模型课程，把全栈拆成「分词器、架构、优化、训练系统」四块（来源：[CS336](#source-stanford-cs336-2025)）。搞懂前两块后，我们来看模型怎么从一堆随机数字练成能聊天的助手。

### 3. RLHF 与 DPO：人类偏好怎么写进参数

把「这个回答比那个更好」变成梯度，工程上有两条主流路线：

- **RLHF（基于人类反馈的强化学习）**：InstructGPT 跑通的三步法——先做 SFT，再拿人类排序数据单训一个打分裁判（**奖励模型**），最后用 PPO 强化学习让语言模型去刷高裁判的打分。在 InstructGPT 的 API 提示评测集上，人类标注员甚至更偏好 13 亿参数的对齐模型，而不是 1,750 亿参数的原始 GPT-3，足见对齐对实用性的撬动（来源：[InstructGPT](#source-instructgpt-2022)）。
- **DPO（直接偏好优化）**：数学上把奖励函数改写进了语言模型自己的概率比里，省掉了单独训奖励模型和在线 RL 采样，直接拿「好答案 / 差答案」成对数据算一个类似分类的损失就能训，稳定又省算力（来源：[DPO](#source-dpo-2023)）。

不管是 RLHF 还是 DPO，本质都不是往模型里写 `if-else` 禁令，而是**用偏好数据重塑概率分布**：把合意回答的概率抬高，把有害或敷衍回答的概率压低。

### 4. Temperature 与 top-p：落笔那一刻怎么抽词

算完整个词表的概率分布后，落笔选哪个 token 由采样参数掌控：

```text
p_i = softmax(z_i / T)
```

- **Temperature（温度 `T`）**：`T` 越小（比如 `0.2`），领先词的概率越接近 100%，回答稳、死板；`T` 越大（比如 `2.0`），大家概率被拉平，回答更有创意也更容易胡说八道。
- **top-p（核采样）**：按概率从高到低累加，一够阈值（比如 `0.8`）就把后面长尾低概率词全砍掉，只在剩下的候选池里抽。

      note: "第 3 步特意把 top_p 设为 1.0 单独观察温度影响：T=0.3 时 8 次全部稳稳落在「测试」；T=2.0 时把低概率选项「删除」拉高到 15.2%，抽 8 次就被抽中了。"
    }

### 6. 幻觉：不是模型在撒谎，是概率机制的副产品

模型一本正经地编造不存在的论文、不存在的 API 参数，这叫**幻觉（Hallucination）**。学术综述把它分成两类：**内在幻觉**（和用户给的原文自相矛盾）和**外在幻觉**（编出了输入里查无实据的内容）（来源：[Survey of Hallucination](#source-hallucination-survey-2022)）。

串起前面三节，你立刻就能看透幻觉的三个源头：

1. **训练目标只奖「像」，不查「真」**：交叉熵压低的是语料里目标词的损失，公式里压根没有一个「去现实世界查真假」的项。
2. **知识有截止日，冷门细节被压缩丢了**：参数是对海量文本的有损压缩，训练截止之后发生的事，或出现太少的冷门事实，模型只能靠统计规律硬补。
3. **采样总得交卷**：哪怕每个候选词都不太靠谱，只要没配拒答机制，采样器也会从分布里挑一个「读着最顺口」的词接着写。

所以光在提示词里喊一句「绝不许编造」治标不治本——真要控幻觉，必须靠**外部检索给证据 + 独立工具/测试校验**。

## 四、上下文窗口的成本与「中间遗忘」

### 1. 为什么窗口越长越贵：`n²` 的算账

标准稠密自注意力里，长度为 `n` 的序列里每个词都要和其他所有词配对打分，光是一层单头的注意力分数矩阵就有 `n × n` 个元素（来源：[Attention Is All You Need](#source-vaswani-2017)）：

长度翻 4 倍，计算量翻 16 倍！工程上用 **FlashAttention** 通过分块把计算塞进 GPU 高速片上内存（SRAM），省掉了把整张巨大的 `n × n` 矩阵来回读写显存的开销，在结果完全等价的前提下大幅提速省显存——不过核心计算量随 `n²` 增长的底子还在（来源：[FlashAttention](#source-dao-2022-flashattention)）。

### 2. 塞得进去，不代表模型用得好

把十万字一股脑倒进大窗口就行了吗？《Lost in the Middle》论文做过多文档问答实验：当关键答案藏在超长上下文的**正中间**时，不少模型的准确率明显低于答案放在**开头或结尾**的时候（来源：[Lost in the Middle](#source-liu-2023)）。

给工程的直接启示很简单：**别把上下文当垃圾桶**——只挑真正相关的片段放进来，把关键指令和核心证据放靠前或靠尾，清理重复和过期信息，重要约束靠外部测试兜底。

## 常见误区与能力边界

- **高概率不等于事实**：模型挑出概率 95% 的词，只代表它在训练语料和当前上下文里最顺口，真假必须交给外部证据和代码校验。
- **对齐不是写死规则**：RLHF 和 DPO 重塑的是概率分布，能大幅提升有用性和安全性，但挡不住所有幻觉，也替代不了应用层的权限检查。
- **单次好看不算评测**：采样带随机性，评估模型改得好不好，必须固定测试集和参数多跑几轮看统计结果。
