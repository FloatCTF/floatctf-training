## 二、`awk` 按列聚合与 `sed` 脱敏替换

在请求行不含未转义空格的标准 Combined 日志样本里，按空白切开后的几个列号很稳定：`$1` 是来源 IP，`$6` 是带引号的方法（`"GET`），`$7` 是**完整请求目标（含查询串，例如 `/api/profile?uid=102`）**，`$9` 是 HTTP 状态码，`$10` 是响应字节数。如果按接口路径分组统计，记得先用 `sub(/\?.*/, "", $7)` 剥离问号后的查询参数。

用 `awk` 挑出所有状态码 `>= 400` 的行，再顺着管道交给 `sort | uniq -c | sort -rn` 排序（来源：[GNU Awk 手册](#source-gnu-gawk)）；再演示用 `sed -E` 替换 IP 末段（来源：[GNU sed 手册](#source-gnu-sed)）：

<TerminalSession
  environment="KALI 终端"
  title="awk 统计异常来源排行 + sed 演示替换 IP 末段"
  steps={[
    {
      cmd: `awk '$9 >= 400 { print $1, $9 }' access.log | sort | uniq -c | sort -rn`,
      out: '      5 203.0.113.77 401\n      5 203.0.113.44 404\n      2 198.51.100.25 403\n      1 198.51.100.31 500',
      note: 'uniq -c 只合并相邻重复行，所以前面必须先 sort，最后再 sort -rn 按次数倒序。一眼就能看出高频 401 与 404 线索。',
    },
    {
      cmd: `head -n 3 access.log | sed -E 's/^([0-9]+\\.[0-9]+\\.[0-9]+)\\.[0-9]+/\\1.xxx/'`,
      out: '198.51.100.xxx - - [25/Nov/2026:09:00:01 +0000] "GET / HTTP/1.1" 200 1842 "-" "Mozilla/5.0"\n198.51.100.xxx - - [25/Nov/2026:09:00:02 +0000] "GET /assets/app.js HTTP/1.1" 200 14210 "http://lab.local/" "Mozilla/5.0"\n198.51.100.xxx - - [25/Nov/2026:09:01:10 +0000] "POST /api/login HTTP/1.1" 200 268 "http://lab.local/" "Mozilla/5.0"',
      note: '圆括号把前三段 IP 捕获为 \\1，只替换最后一段。sed 默认只打印到屏幕，不会改动原 access.log。注意：这只是正则替换演示，外发真实生产日志前还必须检查查询串里的 token/手机号、Referer、内网域名与其他敏感字段。',
    },

## 三、用 `jq` 精准解析结构化 JSON

现代后端接口、云平台告警与审计系统普遍吐出 JSON。不要用 `grep` 和 `sed` 去硬抠 JSON——哪怕对方多加一个换行或改了字段顺序，正则就会碎掉。交给专门的 JSON 处理器 **`jq`**（来源：[jq 手册](#source-jq-manual)）：

<TerminalSession
  environment="KALI 终端"
  title="用 jq 筛选异常事件并按状态码分组计数"
  steps={[
    {
      cmd: `jq -r '.events[] | select(.status >= 400) | "\\(.id)\\t\\(.status)\\t\\(.ip)\\t\\(.path)"' audit-events.json`,
      out: 'evt-02\t404\t203.0.113.44\t/.env\nevt-03\t404\t203.0.113.44\t/.git/config\nevt-04\t401\t203.0.113.77\t/api/login\nevt-05\t403\t198.51.100.25\t/api/profile?uid=102\nevt-06\t500\t198.51.100.31\t/api/checkout',
      note: '.events[] 展开数组，select() 按数值筛选，-r 去掉外层 JSON 双引号，直接产出清爽的制表符表格。',
    },
    {
      cmd: `jq '.events | group_by(.status) | map({status: .[0].status, count: length})' audit-events.json`,
      out: '[\n  {\n    "status": 200,\n    "count": 1\n  },\n  {\n    "status": 401,\n    "count": 1\n  },\n  {\n    "status": 403,\n    "count": 1\n  },\n  {\n    "status": 404,\n    "count": 2\n  },\n  {\n    "status": 500,\n    "count": 1\n  }\n]',
      note: 'group_by(.status) 按状态码分桶，map(...) 把每一桶压成 {status, count} 摘要对象。',
    },
  ]}
/>

<Callout type="note" title="把 curl 和 jq 接成日常习惯">
以后调任何 JSON 接口，直接在末尾接一条管道 `| jq .`（美化缩进）或 `| jq -r .access_token`（取单个字段，就像第 39 课登录拿 JWT 那样），比肉眼在压缩成一行的 JSON 里找字段省十倍力气。
</Callout>

<KeyTakeaway>
纯文本筛行用 grep -E，列结构聚合用 awk 配 sort/uniq（按接口分组记得剥离 $7 里的查询串），行内替换用 sed -E（真实外发前须全面排查敏感字段），嵌套 JSON 一律交给 jq；在 shell 里写表达式优先用单引号防变量误展开，状态码高发是排查线索而非最终定性。下一课我们下潜一层，看看程序跑在 Linux 操作系统里时的虚拟内存、系统调用与服务配置。
</KeyTakeaway>
