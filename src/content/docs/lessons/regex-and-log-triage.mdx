`198.51.100.25 - - [25/Nov/2026:09:04:11 +0000] "GET /api/profile?uid=102 HTTP/1.1" 403 96 ...`

## 二、`awk` 按列聚合与 `sed` 替换演示

在请求行不含未转义空格的标准 Combined 日志里，按空白切开后的列号很固定：`$1` 是来源 IP，`$6` 是带引号的方法（`"GET`），`$7` 是**完整请求目标（带着查询串，比如 `/api/profile?uid=102`）**，`$9` 是状态码，`$10` 是响应字节数。要按纯接口路径汇总时，先用 `sub(/\?.*/, "", $7)` 把问号后面的参数裁掉。

下面用 `awk` 筛出状态码 `>= 400` 的行，交给 `sort | uniq -c | sort -rn` 排频次（来源：[GNU Awk 手册](#source-gnu-gawk)），再用 `sed -E` 演示把 IP 末段替换掉（来源：[GNU sed 手册](#source-gnu-sed)）：

<TerminalSession
  environment="KALI 终端"
  title="awk 统计异常来源排行 + sed 演示替换 IP 末段"
  steps={[
    {
      cmd: `awk '$9 >= 400 { print $1, $9 }' access.log | sort | uniq -c | sort -rn`,
      out: '      5 203.0.113.77 401\n      5 203.0.113.44 404\n      2 198.51.100.25 403\n      1 198.51.100.31 500',
      note: 'uniq -c 只合并相邻重复行，所以前面必须先 sort，最后再 sort -rn 按次数倒排。高频 401 和 404 立刻浮出来。',
    },
    {
      cmd: `head -n 3 access.log | sed -E 's/^([0-9]+\\.[0-9]+\\.[0-9]+)\\.[0-9]+/\\1.xxx/'`,
      out: '198.51.100.xxx - - [25/Nov/2026:09:00:01 +0000] "GET / HTTP/1.1" 200 1842 "-" "Mozilla/5.0"\n198.51.100.xxx - - [25/Nov/2026:09:00:02 +0000] "GET /assets/app.js HTTP/1.1" 200 14210 "http://lab.local/" "Mozilla/5.0"\n198.51.100.xxx - - [25/Nov/2026:09:01:10 +0000] "POST /api/login HTTP/1.1" 200 268 "http://lab.local/" "Mozilla/5.0"',
      note: '圆括号把前三段捕获成 \\1，只替换最后一段。sed 默认只输出到屏幕，不会改原文件。注意这只是替换演示：外发真实日志前，还得把查询串里的令牌、手机号、Referer 和内网域名一并查干净。',
    },
  ]}

## 三、用 `jq` 解析结构化 JSON

现代 API、告警和审计日志大多吐 JSON。别拿 `grep` 和 `sed` 去硬抠 JSON——对方只要换个缩进或调换字段顺序，正则就会失效。直接交给专门的 JSON 工具 **`jq`**（来源：[jq 手册](#source-jq-manual)）：

<TerminalSession
  environment="KALI 终端"
  title="用 jq 筛选异常事件并按状态码分桶计数"
  steps={[
    {
      cmd: `jq -r '.events[] | select(.status >= 400) | "\\(.id)\\t\\(.status)\\t\\(.ip)\\t\\(.path)"' audit-events.json`,
      out: 'evt-02\t404\t203.0.113.44\t/.env\nevt-03\t404\t203.0.113.44\t/.git/config\nevt-04\t401\t203.0.113.77\t/api/login\nevt-05\t403\t198.51.100.25\t/api/profile?uid=102\nevt-06\t500\t198.51.100.31\t/api/checkout',
      note: '.events[] 展开数组，select() 按数值筛，-r 去掉外层 JSON 引号，直接印出干净的制表符表格。',
    },
    {
      cmd: `jq '.events | group_by(.status) | map({status: .[0].status, count: length})' audit-events.json`,
      out: '[\n  {\n    "status": 200,\n    "count": 1\n  },\n  {\n    "status": 401,\n    "count": 1\n  },\n  {\n    "status": 403,\n    "count": 1\n  },\n  {\n    "status": 404,\n    "count": 2\n  },\n  {\n    "status": 500,\n    "count": 1\n  }\n]',
      note: 'group_by(.status) 按状态码分组，map(...) 把每组压成 {status, count} 摘要对象。',
    },
  ]}
/>

<Callout variant="info" title="把 curl 和 jq 接成习惯">
调 JSON 接口时，在末尾顺手接一个 `| jq .`（自动缩进着色）或 `| jq -r .access_token`（直接抽字段，就像第 39 课拿 JWT 那样），不用再肉眼去翻挤成一行的响应体。
</Callout>

<KeyTakeaway>
纯文本筛行找 grep -E，列结构聚合用 awk 接 sort/uniq（按接口统计先裁掉 $7 里的查询串），行内替换用 sed -E，嵌套 JSON 交给 jq。在 shell 里写表达式优先包单引号防误展开；日志里的高频异常状态码是排查入口，不是最终定性。
</KeyTakeaway>
