## 二、栈帧：一次调用留下的东西

### 1. 逐行看 noswap

回到引导问题。点「下一步」，看每执行一行之后内存里的样子：

<CodeStepper
  client:visible
  trace={noswapTrace}
  view="memory"
  title="swap(x, y) 到底换了谁"
  eyebrow="STEP THROUGH / C 的栈"
  intro="留意第 3 步：swap 被调用时右边多出来的那一块，以及 a、b 和 x、y 的地址。"
/>

程序运行时，系统给它一块专门的内存，叫**栈**。每调用一次函数，就在栈上划出一块给这次调用使用，叫**栈帧**，里面放着这个函数的参数和局部变量。函数返回时，这块栈帧就作废了。

<DataTable
  caption="调用 swap(x, y) 的全过程"
  headers={["时刻", "栈上的变化"]}
  rows={[
    ["调用之前", "只有 main 的栈帧，里面是 x 和 y"],
    ["调用的瞬间", "多出 swap 的栈帧。把 x 的值 3 复制给 a，把 y 的值 5 复制给 b"],
    ["swap 执行期间", "a、b、tmp 在 swap 的栈帧里变来变去。main 的栈帧没有人碰"],
    ["swap 返回", "swap 的栈帧作废，a、b、tmp 不复存在"],
  ]}
  columnRatios={[1, 4]}
/>

关键在第二行：传给函数的是**值的副本**。`a` 和 `x` 是两块不同的内存，只是一开始内容相同。C 的参数全部是这样传的。（来源：[N1570](#source-n1570)、[Beej's Guide: Functions](#source-beej-functions)）

要让函数真正改到调用者的变量，需要把变量的地址传过去。这是第 23 课指针的内容，到时会把这个 `swap` 改对。

  steps={[

    { cmd: './fact', out: '6' },

从图里读出三件事：

- 同一个函数被调用三次，就有三个栈帧，三个互不相干的 `n`。
- 后调用的先返回。最里面的 `fact(1)` 先结束，然后是 `fact(2)`，最后是 `fact(3)`。「栈」这个名字就是这么来的：后放上去的先拿走。
- 三个 `n` 的地址依次是 `…ebfc`、`…ebdc`、`…ebbc`，越晚调用的越小。在这台机器上，栈是朝着低地址方向长的。

## 三、局部变量的一生

### 1. 用之前要赋值

函数里声明的变量叫**局部变量**。它在函数被调用时出现，在函数返回时消失。如果声明时不给初值，它里面是什么？

<CodeFile file="labs/c-functions-and-stack/uninit.c" mark="4" />

<TerminalSession
  title="没有赋过值的变量"
  steps={[
    {
      cmd: 'gcc -Wall uninit.c -o uninit',
      out: 'uninit.c: In function ‘main’:\nuninit.c:5:5: warning: ‘n’ is used uninitialized [-Wuninitialized]\n    5 |     printf("%d\\n", n);\n      |     ^~~~~~~~~~~~~~~~~\nuninit.c:4:9: note: ‘n’ was declared here\n    4 |     int n;\n      |         ^',
      note: '-Wall 发现了：n 还没有赋值就被用了。',
    },
    { cmd: './uninit', out: '0', note: '这一次打印的是 0。不要相信它。' },
  ]}
/>

C 不会替你把变量清零。声明 `int n;` 只是在栈帧里划出 4 个字节，里面是这块内存上一次被使用时留下的内容。这次碰巧是 0，下次、换个程序、换个编译选项，可能是任何数。标准的说法是它的值**不确定**。（来源：[N1570](#source-n1570)）

规矩很简单：**声明变量的同时给它初值。**

### 2. 栈不是无限的

<CodeFile file="labs/c-functions-and-stack/forever.c" note="down 每次都再调用自己，永远不返回。" />

<TerminalSession
  title="一直调用，从不返回"
  steps={[
    { cmd: 'gcc forever.c -o forever', note: '这次故意不加 -Wall。加了的话 gcc 会直接警告 infinite recursion detected。' },
    { cmd: './forever', out: 'zsh: segmentation fault  ./forever', note: '程序被系统强行终止。有的系统会在中间多显示 (core dumped)，意思是系统顺手保存了崩溃时的内存。' },
    { cmd: 'echo $?', out: '139', note: '退出状态是 128 加 11。11 是段错误这个信号的编号。' },
  ]}
/>

每调用一次 `down`，栈上就多一个栈帧，而它们永远等不到返回。栈的大小有限，很快被用完，程序再想往外写时碰到了不属于它的内存，系统就把它终止了。这种终止叫**段错误**（segmentation fault），之后几课还会以别的方式遇到它。（来源：[Zsh: Shell Grammar](#source-zsh-grammar)、[signal(7)](#source-man-signal7)）

<KeyTakeaway>
每调用一次函数，栈上就多出一个栈帧，存放这次调用的参数和局部变量；函数返回，栈帧作废。参数是调用者那边的值的副本，所以在函数里改参数改不到调用者的变量。局部变量不赋初值时，里面是内存里原来留下的内容。递归时每一层调用都有自己的栈帧，栈的空间有限，没有终止条件的递归会以段错误结束。
</KeyTakeaway>
