## 引导问题：后台只监听 `127.0.0.1`，人在外面怎么连进去

线上部署有一条常见边界：数据库（3306/5432）、缓存（6379）和内部监控口（9090）**只监听服务器自己的 `127.0.0.1`**，不直接绑在公网 `0.0.0.0`。

从本地电脑访问远端主机的 `127.0.0.1:9090`，最容易混淆的是**两个 `127.0.0.1` 各自属于哪台机器**；而遇到建连失败或想核实流量是否加密，则要靠 **`tcpdump`** 在对应网卡直接查看分组。

## 一、SSH 密钥认证、隔离练习配置与 `~/.ssh/config`

公网 22 端口常遭遇批量弱口令撞库，生产主机一般关闭密码登录，改用 **SSH 公钥认证**（来源：[ssh(1)](#source-openssh-ssh)、[sshd_config(5)](#source-openssh-sshd-config)）：私钥保存在客户端，公钥（`.pub`）写入远端 `authorized_keys`。按 RFC 4252 §7，登录时客户端用私钥对**本次密钥交换生成的会话标识（session identifier）与认证请求字段**签名，服务端用 `authorized_keys` 中对应的公钥验签，全程既不传输密码也不传输私钥。

为了做本机自测时不碰你真实的 `~/.ssh/authorized_keys` 和系统 `/etc/ssh/sshd_config`，所有练习文件统一放进隔离目录 `~/lab/ssh-lab`：

## 三、用 `tcpdump` 与 Wireshark 看清真实流量

前面几课一直在应用层看 `curl` 和浏览器输出。遇到「请求发出去没响应」「到底走没走加密」「DNS 到底解析到哪里」，就需要直接在对应网卡上抓包定位。

<Callout variant="warning" title="抓包边界">
只抓自己本机回环（`lo`）、练习虚拟机网卡或明确授权网段的流量，不对公共网络或他人设备做被动嗅探。
</Callout>
