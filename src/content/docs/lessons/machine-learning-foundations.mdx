## 引导问题：机器怎样从例子里学会判断

先看一个你每天都在用的功能：垃圾邮件过滤。

如果要你手写程序来拦垃圾邮件，第一反应通常是列规则：

```text
正文出现「免费领取」  → 风险分 +3
发件域名在黑名单里    → 风险分 +5
总分达到 5           → 放进垃圾箱
```

这种写法刚上线时挺好用，过两周就头疼了：骗子把「免费领取」改成「免·费·领」，换个新域名，你就得连夜加 `if`。规则越堆越多，还会互相打架。

机器学习换了条思路：**人不直接写判断条件，而是把几十万封标好「是垃圾 / 不是垃圾」的历史邮件交给程序，让程序自己调出一套数字规律**，用来判明天收到的新邮件。

整个过程就六步，也是后面所有 AI 课程的共同底盘：

```text
现实需求 → 收集带答案的例子 → 把例子变成数字（特征）
        → 选模型 + 定评分尺子（损失） → 自动调参数（优化）
        → 拿没见过的题考试（独立评估） → 上线后持续盯盘
```

这一课我们就按这个顺序走一遍：怎么把需求翻译成学习问题，数据该怎么收拾干净，模型怎么算预测和误差，梯度下降怎么找路，以及怎么防止模型「背题」而不真懂。

## 一、先把现实问题翻译成学习问题

### 1. 先分清三个常混的词：AI、机器学习、深度学习

新闻里动不动全叫「AI」，写代码时得把这三个圈分开（来源：[What is Machine Learning?](#source-google-intro-ml)、[Machine Learning Glossary](#source-google-ml-glossary)、[Dive into Deep Learning](#source-d2l-index)）：

- **人工智能（AI）**范围最大：只要让机器完成原本需要人动脑的任务（下棋、看图、翻译、写规则拦诈骗），都算 AI。早年的纯规则专家系统也是 AI。
- **机器学习（ML）**是实现 AI 的一条路：不写死规则，靠数据自动调整内部参数。
- **深度学习（DL）**是机器学习里最火的分支：把很多层神经网络叠起来，自动从像素、文字里提炼特征，这是下一课的主角。

点一点下面三个嵌套层，看看各自典型做法：

<AiMlDlExplorer client:visible motionLevel="subtle" />

什么时候该写死规则，什么时候才上机器学习？记住一句大白话：**规则少、边界死、审计要求百分百可解释（比如税率、白名单），老老实实用 `if-else`；模式复杂、天天在变、历史样本又多（比如垃圾邮件、风控、识图），再上机器学习。**

### 2. 定义学习问题，至少要说清五件事

只说「帮我训一个拦垃圾邮件的 AI」，工程上没法开工。至少得先敲定五个问题：

1. **例子长什么样（数据分布）**：给全体用户用，还是只针对企业邮箱？样本覆盖的时间跨度有多长？
2. **怎么变成数字（特征表示）**：只看正文词频，还是连链接数量、发件历史一起算？
3. **允许学哪类规律（模型）**：用直线打分（逻辑回归）、决策树，还是神经网络？
4. **怎么算猜得好不好（训练目标）**：选哪个损失函数？要不要加惩罚项防过拟合？
5. **怎么算上线合格（评估与代价）**：漏放一封广告和误删一封录取通知，哪个代价更大？

把这五件事对齐，后面的数据采集、调参和验收才不会跑偏。

### 3. 参数与超参数：谁自己学，谁由人拍板

训练里经常蹦出两个词，其实很好分：

- **参数（Parameter）**：模型在训练中**自己调出来**的数字，比如直线里的斜率 `w` 和截距 `b`。你可以把它想成刷题刷出来的「题感」，没人直接写给你，是反复对答案练出来的。
- **超参数（Hyperparameter）**：开训之前**人手动定好**的档位，训练时不会自己改。最常见的两个是**学习率**（每步调参数的幅度）和**批量大小**（一次看多少道题再改一次参数）。

```text
训练阶段：输入 x + 当前参数 θ → 算出预测 ŷ → 对照答案算误差 → 更新 θ
推理阶段：输入新 x + 固定参数 θ → 直接输出预测 ŷ（不再改参数）
```

平时线上调用模型都属于推理，参数是锁死的；只有重新训练或微调，才会产生新版本参数。

## 三、模型怎样猜，误差怎样算

前面说学习是「照着打分尺子自动改参数」。这一节我们就把最基础的几把尺子造出来。

### 1. 线性回归与 MSE：先拿四套房画一条直线

假设手里有四套房子的成交记录：`50 m² → 205 万`、`68 m² → 262 万`、`85 m² → 334 万`、`102 m² → 401 万`。

肉眼一看，面积越大价格越高，大致排在一条直线附近。我们把猜想写成公式：

```text
ŷ = w × x + b
```

`x` 是面积，`w` 是每平米单价，`b` 是基础截距，`ŷ` 是模型猜的价格。这就是**线性回归**。

现在要给不同的直线打分：画得歪不歪？对每套房量一下「猜的价格」和「真实成交价」的竖直落差 `ŷᵢ - yᵢ`。落差有正有负，直接相加会正负抵消，所以先平方再取平均——这就是**均方误差（MSE）**（来源：[Linear regression: Loss](#source-google-linear-loss)）：

```text
MSE = (1 / N) × Σ (ŷᵢ - yᵢ)²
```

平方带来两个好处：一是正负误差不会抵消，二是猜偏 50 万的惩罚比猜偏 5 万重 100 倍，逼着模型先把离谱的大错修掉。

亲手拖一拖下面两个滑杆，看看 `w` 和 `b` 怎么拉动直线、红色误差线和 MSE 怎么跟着变：

你会发现，哪怕只有两个参数，靠人眼瞎拖也很难一下凑到最低点。真到成千上万个参数时，就必须让算法自己顺着误差往低处找——这正是第四节要讲的梯度下降。

### 2. 逻辑回归与二元交叉熵：把分数压成概率

预测房价可以输出 205 或 401，但判断「是不是垃圾邮件」需要的是 **0 到 1 之间的概率**。

如果线性式子 `z = wᵀx + b` 算出来个 `8.3` 或 `-5`，直接当概率肯定不行。我们给它套一个 S 形函数 **sigmoid**，把任意实数平滑压进 `(0, 1)` 区间：`z = 0` 刚好对应 `0.5`，`z` 越大越接近 `1`，`z` 越小越接近 `0`（来源：[Calculating a probability with the sigmoid function](#source-google-logistic-sigmoid)）：

```text
z = wᵀx + b                   （先算线性分数，叫 logit）
p = σ(z) = 1 / (1 + e⁻ᶻ)      （sigmoid 压成概率）
```

分类任务的打分尺子也要升级。我们不仅要罚「猜错」，更要重罚**「瞎猜还特别自信」**。实现这个效果的损失函数叫**二元交叉熵（BCE / Log Loss）**（来源：[Logistic regression: Loss and regularization](#source-google-logistic-loss)）：

```text
BCE = -[y · ln(p) + (1 - y) · ln(1 - p)]
```

注意这里的 `ln` 是自然对数（以 `e` 为底）。当真实标签 `y = 1` 时，代入两个数就能看出它的脾气：

```text
模型猜 p = 0.8  → 损失 = -ln(0.8) ≈ 0.223  （靠谱，轻微扣分）
模型猜 p = 0.1  → 损失 = -ln(0.1) ≈ 2.303  （错得离谱还很笃定，重罚十倍！）
```

### 3. Softmax：从二选一扩展到多选一

如果任务变成识别手写数字 `0–9`（10 个互斥类别），模型会给每个类算一个 logit 分数。把这一组分数变成「加起来刚好等于 1 的一组概率」，用的就是 **softmax**（来源：[Softmax Regression](#source-d2l-softmax)）：

```text
p(类别 k) = exp(zₖ) / Σⱼ exp(zⱼ)
```

多分类的交叉熵更简单，只盯真实类别拿到的概率：`CE = -ln(p_真实类别)`。如果一张图允许同时打多个标签（比如既包含「行人」又包含「红绿灯」），那就对每个标签单独套 sigmoid，不用 softmax。

### 4. 表格数据的另一条主线：树模型与集成

做表格数据（风控、用户流失、房价表）时，实战里往往先试**树模型**而不是神经网络。决策树不画平滑直线，而是像玩猜猜看一样连环提问：「金额 > 1000 吗？」「开户不满 30 天吗？」，一路把样本切进越来越纯的子组。它不用做特征归一化，也很容易把判断依据讲给业务方听。

### 5. 损失、指标与正则化：别把训练尺子和业务目标混为一谈

基于梯度优化的模型（线性回归、逻辑回归、神经网络）在训练时通常需要可微（或存在次梯度）的**损失函数**（树模型则按划分纯度选切点），并常在目标后面加上**正则化项** `λΩ(θ)` 惩罚过大的权重，防止模型为了迁就个别噪点把曲线拧成麻花（来源：[L2 regularization](#source-google-l2-regularization)）：

```text
训练总目标 J(θ) = 样本平均损失 + λ × 复杂度惩罚
```

但线上老板和用户关心的不是「交叉熵降了 0.03」，而是「漏了多少诈骗」「误封了多少正常账号」「接口有没有超 100 毫秒」。所以工程上分四层把关：**损失函数**管训练梯度，**离线指标**（Recall、PR-AUC）选模型和阈值，**业务指标**看真实体验，**硬规则**（白名单、延迟上限）在线上兜底。

## 四、优化：误差怎样变成参数更新

有了损失函数，训练就变成了一个找最低点的寻路问题。

### 1. 梯度：蒙着眼睛下山时的坡度指南针

想象你蒙着眼睛站在一座雾蒙蒙的山坡上，想走到谷底。虽然看不见整座山，但用脚探一下周围，总能感觉到哪个方向坡最陡。往最陡的**下坡方向**迈一步，停下来再探一次，一步步就能蹭到谷底。

在数学里，海拔高度就是**损失**，你的坐标就是**参数**，指向最陡**上坡**方向的向量叫**梯度**。所以往反方向走，就是**梯度下降**（来源：[Linear regression: Gradient descent](#source-google-linear-gradient)）。

<LossLandscape />

先拿最简单的单参数模型 `ŷ = wx` 现场手算一步。假设有一个样本 `x = 2, y = 4`，初始乱猜 `w = 0.5`，学习率 `η = 0.05`：

```text
1. 前向预测：ŷ = 0.5 × 2 = 1
2. 算平方损失：L = (1 - 4)² = 9
3. 算梯度：dL/dw = 2(ŷ - y)x = 2 × (1 - 4) × 2 = -12
4. 更新权重：w_新 = 0.5 - 0.05 × (-12) = 1.1
```

## 五、泛化：刷题满分不代表考试能过

把 100 道练习题答案倒背如流的学生，上考场换张新卷子照样可能不及格。机器学习里，模型在**训练时没见过的新数据**上表现同样稳，才叫**泛化**（来源：[Overfitting](#source-google-overfitting)）。

### 1. 三份数据各司其职，谁都别越界

要测真本事，至少把数据分成三份，各干各的活：

- **训练集（平时练习题）**：算损失、算梯度、改参数，全靠它。
- **验证集（模拟考）**：用来挑模型结构、调学习率和多项式阶数。但模拟卷刷多了，人也会不知不觉顺着模拟卷偏科。
- **测试集（真正的高考）**：全程封存，只在最终定案后考**一次**，报告最终成绩。一旦偷看测试集并回头改模型，这份成绩就废了。

把训练误差和验证误差摆在一起看，就能判断模型卡在哪（来源：[Bias-Variance Analysis](#source-cs229-bias-variance)）：

### 2. 怎么切分数据，怎么堵住数据泄漏

不是所有数据都能随便打乱随机切分（来源：[scikit-learn Cross-validation](#source-sklearn-cross-validation)、[AWS Splits and data leakage](#source-aws-splits-leakage)）：

- **带时间顺序的任务**（股价、销量、风控）：必须按时间切，过去做训练、未来做验证，绝不能拿明天的数预测昨天。
- **同实体多条记录**（同一个病人拍 5 张片、同一个用户发 10 条评论）：同一个人必须全部划在同一边（GroupKFold），否则模型只是认出了「这人我见过」。
- **样本量不大时**：用 K-fold 交叉验证轮流当验证集，估计分数更稳，但最终测试集依然要单独锁好。

**数据泄漏**就是考前泄题，最常见的两种坑（来源：[scikit-learn Common pitfalls](#source-sklearn-data-leakage)）：

1. **预处理泄漏**：切分前拿全量数据做标准化或特征选择，把测试集的均值分布偷偷带进了训练。用 `Pipeline` 把预处理包进训练流程即可根治。
2. **穿越字段泄漏**：预测贷款会不会违约，特征里塞了个「催收次数」。催收发生在违约**之后**，历史表里它和标签几乎 100% 相关，但真正放贷审批那一刻你根本拿不到这个字段。

### 3. 选错指标，好坏会完全看反

假设 1,000 笔交易里只有 10 笔欺诈。一个啥都不干、闭着眼全猜「正常」的摆烂模型，**准确率（Accuracy）高达 99%**，但欺诈召回率是 **0%**！只要类别极不平衡，准确率就会骗人（来源：[Accuracy, precision, and recall](#source-google-classification-metrics)、[scikit-learn Model evaluation](#source-sklearn-model-evaluation)、[Probability calibration](#source-sklearn-calibration)）。

遇到正负样本严重失衡，先换指标（改看 **PR-AUC** 和分场景 **Recall**），再用三招组合拳对症处理：

1. **改类别权重**：训练时给少数类的错题加倍扣分。scikit-learn 的 `class_weight='balanced'` 按频率反比自动算权重 `n_samples / (n_classes × 各类样本数)`（来源：[LogisticRegression class_weight](#source-sklearn-class-weight)）。
2. **重采样**：只对**训练集**做少数类过采样或多数类欠采样，验证集和测试集千万别动，否则考试分布失真。
3. **挪分类阈值**：谁规定概率必须过 `0.5` 才报警？按误杀和漏放的真实业务成本，在 PR 曲线上挑最划算的切点。

## 常见误区与能力边界

- **训练和推理不是一回事**：训练改参数，线上推理参数固定不动。
- **损失低不等于业务好**：交叉熵只是训练抓手，最终还得拿离线业务指标、错误代价和硬约束说话。
- **概率不是最终动作**：输出 `0.62` 要不要拦截，取决于你按业务代价定的阈值，且概率本身要查校准。
- **永远别信没防泄漏的高分**：先切分再拟合预处理器，剔除「事后才知道」的穿越字段，上线前只在最终测试集考一次。

这一课我们亲手拟合的是直线，也见识了树模型怎么在表格上做折线切分。但面对像 XOR 那种对角交错的图案，或者成千上万像素的手写数字，单层线性打分就力不从心了。下一课《神经网络：从神经元到架构》，我们在完全相同的训练闭环里装进隐藏层和反向传播，看看多层网络是怎么把复杂特征一层层搓出来的。

<KeyTakeaway>
记住本课最核心的两幅画：**山坡上的下山轨迹**——梯度指坡向，学习率太大就撞墙甚至爆炸；**训练与验证误差的分叉**——阶数太低两边都差（欠拟合），阶数太高训练趋近 0 而验证抬头（过拟合）。先切分防泄漏，再按业务代价选指标，才是完整的机器学习训练验收闭环。
</KeyTakeaway>
